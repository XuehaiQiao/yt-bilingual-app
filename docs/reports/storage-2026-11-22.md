# 存储现状测量（任务 7 第一步「量」）

> 对应 [docs/计划-v1.1.md](../计划-v1.1.md) 任务 7 §8.2「第一步 · 量」：先量后限，阈值由真实分布决定，不拍脑袋。
> 本文只记录测量结果与对下一步的含义；**不实现任何清理/配额逻辑**。

## 0. 怎么重跑

```bash
# 仓库根目录
cd backend && venv/bin/python ../scripts/storage_stats.py \
    --db ../data/app.db --users-dir ../data/users --guests-dir ../data/guests
# 机器可读
cd backend && venv/bin/python ../scripts/storage_stats.py \
    --db ../data/app.db --users-dir ../data/users --guests-dir ../data/guests --json
```

- 快照时间：2026-11-22T00:14:58+08:00（Asia/Shanghai）
- 环境：macOS；Python 3.12（backend venv）与 3.8.8（系统 python3）均可跑；SQLite 3.35.4，`dbstat` 可用（表大小精确到页，含索引）
- 只读校验：SQLite 以 `file:…data/app.db?mode=ro` 打开并 `PRAGMA query_only=ON`；脚本自身不写库——同一次运行紧邻前后库文件 SHA256 一致。**但这是活动库**：测量期间其它进程/进程内业务在写（两次快照之间 `learning_events` 从 1,342 涨到 1,343），所以各段数字是同一时刻的快照，重跑会有少量行差异（页级大小通常不变）。
- 脚本不删文件、不联网、无写入参数；`data/users`、`data/guests` 目录数在多次运行前后不变。

### 1.1 按归属拆账（关键结论）

| 桶 | 行数 | 估算字节 |
| --- | ---: | ---: |
| 真实用户（users 表 ∪ data/users 目录，去重 12 个） | 1,164 | 542.01 KB |
| 匿名 user_id（有 user_id，但不在 users 表、也没有用户目录） | 2,975 | 1.65 MB |

- 匿名 id 的形状是「一个 id 一条记录」：`weekly_reports` 1,582 行 / **1,581 个** user_id，`learning_events` 818 行 / **807 个** user_id，`ai_usage` 559 行 / 154 个。

- 游客在库里的痕迹很少：`watch_events` 14 行 / 11 个 `guest_hash`，`placement_sessions` 2 行 / 2 个。游客占用主要是目录（见 §3），不是库。
- 全局缓存（可重建类）共 576.00 KB：`content_teaching_analysis` 31 行 352.00 KB + `content_difficulty` 147 行 224.00 KB，正是任务 7 §8.2 要按「30 天未访问 + LRU」淘汰的那一类。

## 5. 对第二步（分类/限流）的直接含义

1. **现在没有配额压力**：最大用户 2.40 MB，第二 883.99 KB。按当前分布订阈值毫无意义（n=12，只有 1 个活跃样本）。若要给一个「安全阀」，建议先取宽松值（例如与导出上限 200 MB 对齐）并只做提示不做硬拒，等真实样本积累后再按 P99 收敛。
2. **游客清理应以「目录数 + 年龄」为主指标，不以字节为主指标**：6,766 目录 / 234.16 KB / 6.21 MB 磁盘，量级全在 inode 和 4 KB 块上。TTL 7 天今天命中 0，但增长约 1,033 个/天，建议同时加数量上限（如 2 万）兜底。
3. **游客清理要同步清库**：库里 1.65 MB（48%）挂在匿名 user_id 上（`weekly_reports` 1,581 个 id、`learning_events` 807 个 id），只删目录不清行，库不会变小。
4. **可重建缓存是唯一安全的自动清理对象**：全局缓存 576.00 KB，符合任务 7 的 LRU 策略；`weekly_reports`/`learning_events` 属于用户可见数据，只能提示、不能自动删（红线）。
5. **注销链路要能清目录**：4 个「目录在、记录无」的残留说明当前注销没有清 `data/users/<id>/`。

## 6. 局限

- 用户库内字节是按行数比例把表总占用摊给用户，**不是精确 per-row**；精确到行需要逐行 `length()` 扫描或 `sqlite3_analyzer`。
- 样本 n=12（其中活跃 1 个），P90/P99 与最大值几乎重合，分位数只说明「当前量级」，**不足以当阈值依据**；`scripts/storage_stats.py` 可随时重跑积累样本。
- 游客目录的 `du` 与 apparent 差 27 倍（6.21 MB vs 234.16 KB），报告中两者都给了；不要只看 `du` 下结论（它含块对齐开销）。
- 本次只测 `data/app.db`；`ecdict.db` 等其它库只作为 `data/` 上下文列出，未按表拆分。
