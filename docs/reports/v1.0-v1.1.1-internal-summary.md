> 范围：v1.0.0 上线（2026-11-21）到 v1.1.1 上线（2026-11-27）  
> 性质：内部复盘，包含已知问题、流程教训与未完成项；不是对外发布稿。  
> 生产基线：`v1.1.1` / `36cfdec` / 迁移 `0033_v1_1_launch`。

## 1. 结论先行

这一周完成了从「能用的 V1」到「可运营、可隔离、可回滚的 V1.1」的过渡：

- v1.0 建立了真实内容 + AI 辅助 + 阅读/复习/练习的完整底座。
- v1.1 补上了账号找回、邮箱验证、额度页、反馈闭环、首启引导和 AI 生成标识。
- v1.1.1 集中修复了上线后暴露的缓存/身份隔离、观影体验、语言点首屏和分级口径问题，并把发布流程沉淀为 Agent/人工两套 runbook。

最终生产验收：**7 项 PASS，1 项 deferred（本地视频观影）**。  
这不是“零问题上线”，但核心学习路径、账号隔离和成本边界已经可验证。

## 3. 交付内容（按工作流）

### 3.1 内容与学习体验

- 免费内容库：精选视频 + 原创双语短文，预置字幕，游客可读。
- YouTube 视频：双语字幕流式生成、SSE 断线续传、句子跟随/点句跳转。
- 文章与公版书：文章导入、公版书阅读、按需翻译、EPUB 导入。
- 本地内容：本地 SRT 剧集；本地视频文件在浏览器标签页内播放，媒体不离开浏览器。
- 观影模式：统一媒体舞台，进入/退出观影不再重建播放器。
- 语言点：按 CEFR 等级标亮，语境释义、习语、文化点，内容级缓存。
- 理解题：答错回到原句/原声。
- 能力画像与周报：CEFR 区间、置信度、学习事实数据。

### 3.2 账号、计费与运营

- 邀请码注册、登录、会话、每用户数据目录。
- 余额账本、预占/结算/释放、严格计费；未登录/游客不能调用 AI。
- 额度页、额度覆盖、日预算/全局日预算。
- v1.1 增加：找回密码、邮箱验证、反馈提交与管理台、首启 3 步引导、AI 生成标识。
- 管理台：用户、额度、反馈、健康、邀请、审计。
- 备份/恢复、迁移演练、Caddy/Docker 部署。

### 3.3 缓存、隐私与身份隔离（v1.1.1 重点）

上线后发现“最近学习串账号”“收藏/订阅串账号”等问题，定位结论：

- 后端 `/api/history` 本身按账号隔离正确。
- 问题主要在前端：用户私有 localStorage 是浏览器级单例，收藏/订阅还把 localStorage 当服务端失败 fallback。
- 跨 tab 登录 B 后，旧 tab 仍显示 A，但请求已按 B 返回。
- 缓存审计还发现：私有 API 缺 `no-store`、bfcache 可恢复旧 DOM、游客目录无 TTL、claim 只搬文件不迁 DB 行。

v1.1.1 已修：

- 收藏/订阅删除全局 fallback，服务端唯一事实源，epoch 拒绝迟到响应。
- `storageScope`：device / guest / u:<userId>；视频、书、导入书、句子、游客词表、任务/搜索按身份隔离。
- 旧 key 一次性迁移，guest claim 合并/清空。
- 跨 tab 单活跃账号：登录/退出广播 + 其他 tab reload。
- 私有 API 默认 `Cache-Control: private, no-store` + `Vary: Cookie`。
- bfcache/pageshow 安全处理；无身份 `/api/history` 不读全局目录。
- 清除本机学习数据入口。

### 3.4 内容分级

- 编辑级 `level` 与算法级 `content_difficulty` 曾出现本地/线上不一致。
- 决策：**算法级为展示准绳**，编辑级只做缺行兜底。
- 生产回填 152 条：serving 122 + curated 30。
- 审计：152 computed / 0 legacy / 0 缺行 / 本地线上展示不一致 0。
- 已知异常：`eci-stand-verb`、`eci-cut-verb`、`pg-the-town-mouse...` 等算法与编辑级差异较大，按“后续优化算法”处理，不手工改展示。
- 本次展示等级变化 129 条，用户已接受。

## 5. 关键问题与处理

### 5.1 v1.0 缓存视频观影黑屏

- 原因：v1.0 缓存 payload 缺 `block.highlights`，前端按数组访问。
- 修复：缺失按空数组兼容；不要求用户清缓存/重译。
- 生产验收 PASS。

### 5.2 进入/退出观影重新加载

- 原因：两套条件布局导致 `VideoPlayer` 卸载重建。
- 修复：共用同一媒体舞台/DOM 节点。
- 生产验收 PASS（iframe/src 不变、时间不回 0）。

### 5.3 语言点首屏慢

- 原因：首次请求对六档 CEFR 候选做并集生成。
- 修复：level-first，当前等级优先，切等级再补缺失词；旧 v6 缓存复用。
- 生产验收 PASS。

### 5.4 最近学习/收藏/订阅串账号

- 原因：前端全局 localStorage、服务端失败 fallback、订阅自动 PUT。
- 修复：P0 fallback 删除 + epoch；P2-50 storage scope + claim；跨 tab reload。
- 生产验收 PASS。

### 5.5 分级不一致

- 原因：线上 `content_difficulty` 全 legacy，本地有 computed。
- 修复：算法级 canonical；生产回填 152 条；审计一致。
- 生产 `free-app-hidden-cost` 显示 B1，验收 PASS。

### 5.6 本地视频观影未通过

- 生产验收仍不可用，用户决定暂不修。
- 记录于 `TASKS/P2-54-local-video-watch-deferred.md`。
- 影响：本地视频路径体验不完整；不影响 YouTube/文章/书主路径。

## 6. 做得好 / 不足

### 做得好

- 内容、AI、阅读、练习、账号、计费能在三周内连成可运行产品。
- 缓存问题发现后没有掩盖：做了三路审计（后端/前端/基础设施），把“看似能登录”拆成可复现证据。
- v1.1.1 没有靠“提醒下次注意”，而是下沉成 storageScope、缓存头、验收脚本、发布门禁。
- 生产回填有 dry-run、审计、备份、可回滚镜像。
- 邀请制 beta 用户量小，给了修复窗口。

### 不足

- v1.1 上线前没有把“账号切换/缓存隔离”列为门禁；单账号验收掩盖了问题。
- 前端长期把 localStorage 当服务端 fallback，属于设计错误，不是单点 bug。
- 测试脚本存在 TEST-STALE/FLAKY；`cefr-lemma` 在功能删除后仍留了很久。
- 本地视频观影在本地验收与生产验收之间有差距，说明 fixture 不能替代真实用户路径。
- 游客 TTL、claim DB 行迁移、月度预算/防刷仍未完成。
- 发布流程是 v1.1.1 才补上的；此前依赖个人记忆。

## 8. 下一步建议

1. **不要立刻开新功能**：先完成 24h/7d 观察和真实旧账号回归。
2. **修本地视频观影前先做生产可控复现**：确认入口、媒体文件识别、能力开关，不要先改数据。
3. **补 guest 生命周期**：TTL、claim 迁 DB 行、清理脚本。
4. **补成本硬边界**：供应商月度硬限额 + 应用月预算 + 异常告警；不要只靠日预算。
5. **把缓存 key 注册表纳入开发门禁**：新增 key 必须声明 scope/TTL/迁移/测试。
6. **保留 v1.1.1 证据**：备份、回填报告、审计、验收 TSV、发布记录至少保留 7 天。
