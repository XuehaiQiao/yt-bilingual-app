## 1. 账号找回与邮箱验证

### 数据

migration `0033_v1_1_launch`：

- `auth_tokens`：一次性 token，**只存 SHA-256**，单次、过期
- `users.email_verified_at`：可空；旧用户 NULL，不强制验证
- `feedback`：反馈表（见 §3）

### API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/password-reset/request` | 恒 200，不枚举邮箱 |
| POST | `/api/auth/password-reset/confirm` | token 单次 + 过期 + 密码策略 |
| POST | `/api/auth/email-verification/request` | 登录态；202 |
| POST | `/api/auth/email-verification/confirm` | token 验证，写 `email_verified_at` |

- 登录/me 响应增加 `emailVerified`（旧字段不变）
- 重置密码只失效该用户会话
- SMTP 可插拔：`SMTP_HOST/PORT/USER/PASSWORD/FROM/PUBLIC_BASE_URL`
- 未配置 SMTP 时 dev outbox；**生产必须配置**，否则用户收不到信

### 前端

- `#/login?reset=<token>` 重置页
- `#/login?verify=<token>` 邮箱验证
- 账户页未验证提示
- token 消费后从 URL 移除

## 2. 用户额度页

### API

`GET /api/quota`（登录；游客 403；未登录 401）

```json
{
  "day": "2026-11-25",
  "resetAt": "2026-11-26T00:00:00+08:00",
  "timezone": "Asia/Shanghai",
  "features": [
    {"feature":"translate","limit":60,"used":3,"remaining":57,
     "resetAt":"2026-11-26T00:00:00+08:00","source":"default"}
  ]
}
```

- `limit=0` = 已关闭
- `source`：`config` / `default` / `user_override`
- 只读；不改变运行时配额

- 我的页额度面板

## 3. 反馈与纠错

### 用户 API

`POST /api/feedback`

```json
{
  "category": "bug|feature|content|other",
  "description": "5–2000 字",
  "requestId": "客户端生成",
  "page": "当前页"
}
```

- 登录/游客均可；限流（登录 5/min、游客 3/min）
- 兼容 `message` 别名
- 响应 `{id, requestId, status}`
- `page` 只校验并写日志；**0033 没有 page 列**，管理台显示“未记录”

### 管理 API

- `GET /api/admin/feedback?status&limit`
- `PATCH /api/admin/feedback/{id}` `{status, adminNote}`

### 管理台

- 「反馈」tab
- 默认 open；筛选 open/resolved/all
- 展开处理状态 + 备注；PATCH 后刷新
- 1440 截图、空态/错误/加载态

## 5. 迁移与数据保护

### 变更面

- 新增 `auth_tokens`、`feedback`

- **不改/不删旧表、不重写行、不改 ID/邮箱/密码/余额/词书/进度**

### 演练结果

从 **0032（v1.0）** 副本：

- 升级 252ms / 回滚 255ms / 整库恢复 1.8s
- 旧表逐表哈希一致
- 50 表 / 15,382 行 / 8 用户 / 92 用户文件不变
- `integrity_check` OK、FK 0
- **PASS**

### 生产步骤

1. 停写
2. `scripts/backup.sh` + 离机副本
3. `scripts/v11_data_snapshot.py` 基线
4. `alembic upgrade head`
5. 迁移后快照比对 + 冒烟
6. 灰度放量

### 重要注意

- **不要拿已升级到 0033 的库直接做回滚演练**：脚本基线会包含新列，回滚后必然报“列被删除”。正确做法是复制一份，副本先降到 0032，再演练。
- 生产 current 若 < 0032，会一次跨多个迁移；0026 会清理旧种子区间且不可逆，必须停写并按 `--from-rev <current>` 演练。
- 回滚三层：代码回滚 → `alembic downgrade 0032_pipeline_timing` → 整库恢复。
- 回滚会丢失 v1.1 新表/验证状态；优先代码回滚。

### 用户感知

- 不强制重新登录
- 不强制邮箱验证
- 不强制新手引导
- 旧 URL/收藏/进度/词书不变
- 新功能渐进展示
