面向开发者：怎么跑起来、怎么改、怎么遵循规格驱动的工作流。

## 本地跑起来

环境要求：Node 18+、Python 3.10+、至少一个模型 Key：[Gemini](https://aistudio.google.com/apikey)（默认）和/或 [DeepSeek](https://platform.deepseek.com/api_keys)（可选，OpenAI 兼容）。

```bash
./setup.sh                       # 安装前后端依赖
cp .env.example .env             # 填入 GEMINI_API_KEY（可选再填 DEEPSEEK_API_KEY）
./start_app.command              # macOS 一键启动
```

手动启动：

```bash
# 后端
cd backend && source venv/bin/activate && uvicorn main:app --port 8000
# 前端
cd frontend && npm run dev        # http://localhost:5173
```

## 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `GEMINI_API_KEY` | 是* | 默认模型（Gemini 各档）的 Key；*与 `DEEPSEEK_API_KEY` 至少配一个 |
| `DEEPSEEK_API_KEY` | 否 | 配了才会在模型选择里出现 DeepSeek（OpenAI 兼容端点，见 `backend/llm.py`） |
| `WHISPER_MODEL` | 否 | 无字幕转写的 Whisper 模型大小，默认 `base` |
| `CORS_ORIGINS` | 公网部署必填 | 允许的跨域来源，逗号分隔；默认 `*` |
| `API_AUTH_KEY` | 公网部署必填 | 设置后所有 `/api` 请求必须带 `X-API-Key`，保护你的模型配额；**与用户会话同时生效，互不替代** |
| `COOKIE_SECURE` | HTTPS 部署必填 | 设为 `1` 时 `ln_session` Cookie 加 `Secure`；本地 HTTP 默认关 |
| `AUTH_DB_PATH` | 否 | 用户/会话 SQLite 路径，默认 `data/app.db` |
| `USER_DATA_DIR` | 否 | 每个登录用户的数据根目录，默认 `data/users`；测试/临时实例可指到 `/tmp` |
| `DATA_DIR` | 否 | `data/` 根目录，默认仓库下 `data/`，也是上面两者的默认父目录 |
| `VITE_API_BASE` / `VITE_API_KEY` | 否 | 前端指向远程后端 / 携带其 Key |
| `HISTORY_DIR` / `SUBTITLES_DIR` / `SENTENCES_DIR` | 否 | 旧版/未登录上下文的历史缓存目录、本地剧集、句子精背数据目录 |
| `LOCAL_DICT_PATH` | 否 | 本地词典 sqlite 路径，默认 `data/ecdict.db`；文件不存在时查词自动走大模型 |

> **安全红线**（[宪法原则 6](../CONSTITUTION.md)）：公网部署前必须设 `API_AUTH_KEY` + `CORS_ORIGINS`，HTTPS 下再设 `COOKIE_SECURE=1`。`start_app.command` 的公网隧道默认关闭，需显式 `ENABLE_TUNNEL=1` 且已设 `API_AUTH_KEY` 才会开。

## 用户体系与数据隔离

后端已内置账号体系，所有 `/api/*`（`/api/auth/*` 与 `/health` 除外）都要求登录：

- `POST /api/auth/signup`、`POST /api/auth/login`：成功返回 `{"user":{"id","email"}}` 并设置 `ln_session` Cookie（httpOnly / SameSite=Lax / 30 天；`Secure` 由 `COOKIE_SECURE` 控制）。
- `POST /api/auth/logout` 清 Cookie 并删除服务端会话；`GET /api/auth/me` 返回当前用户，未登录为 `401 {"detail":"未登录"}`。
- 密码只存 Argon2id 哈希；会话表只存 token 的 sha256，Cookie 里是随机 token。登录失败统一 401、不区分邮箱是否存在；同一 IP 失败过多会临时 429（内存限流）。
- 本地前后端分离开发时，`localhost` 与 `127.0.0.1` 属于不同 site，浏览器不会带 SameSite=Lax 的会话 Cookie；前后端统一用同一个主机名（都 `127.0.0.1` 或都 `localhost`）或走 Vite 代理。

数据目录（均在 gitignore 的 `data/` 下）：

```
data/app.db                  # 用户 + 会话（AUTH_DB_PATH 可覆盖）
data/users/<user_id>/        # 每个用户隔离的数据根（USER_DATA_DIR 可覆盖）
  history/                   # 视频/剧集缓存 + dictionary_cache.json
  favorites.json
  subscriptions.json
```

- 后端代码统一通过 `backend/storage.py` 取路径；未登录上下文（测试/脚本）回落到 `HISTORY_DIR`。新增持久化功能时不要再直接拼 `HISTORY_DIR`。
- 可选 `API_AUTH_KEY` 是部署级第二道门：设了它就必须同时带 `X-API-Key`，不会因为有会话而跳过。
- **旧数据迁移**：升级后旧 `history/` 不会自动归属任何账号；需要保留时，登录拿到 user_id（`/api/auth/me` 或查 `data/app.db`），把旧 JSON 移到 `data/users/<user_id>/history/`，`favorites.json` / `subscriptions.json` 移到 `data/users/<user_id>/`。迁移前先备份。
- 测试：`backend/tests/conftest.py` 的 `client` 夹具会自动注册/登录测试用户并把 Cookie 注入 TestClient，`history_dir` 返回该用户隔离后的目录；认证与隔离契约见 `backend/tests/test_auth.py`。

## 本地词典（可选，ECDICT）

点词查词典默认**先查本地词典、再调大模型**：本地命中直接返回（秒回、零模型成本），未命中才走原来的模型链路。不装词典也能跑，只是每个词都会走大模型。

```bash
# 仓库根目录：下载 ECDICT CSV（约 63 MB）并构建 data/ecdict.db（约 104 MB）
python3 scripts/fetch_dictionary.py

# 其他用法
python3 scripts/fetch_dictionary.py --force                     # 已有也重建
python3 scripts/fetch_dictionary.py --csv /tmp/ecdict.csv       # 用已下载的 CSV
python3 scripts/fetch_dictionary.py --dest /path/to/ecdict.db   # 自定义输出路径
```

- 目标文件已存在时脚本自动跳过（幂等）；下载/构建失败会清理临时文件并给出重试提示。
- 数据默认在 `data/ecdict.db`（已 gitignore），运行时可用 `LOCAL_DICT_PATH` 覆盖；也可以把 ECDICT 官方 sqlite 版（`ecdict-sqlite-28.zip` 里的 `stardict.db`）直接放到该路径，表结构兼容。
- **许可证结论**：ECDICT 仓库代码是 MIT（Copyright (c) 2025 Linwei）；但词典**数据**由作者从 EDictAZ、四六级/GRE 词表、`cdict-1.0-1.rpm`、BNC 语料库等多来源整理，各来源授权状况不一。所以本仓库**不打包、不提交**数据，只在本机下载——自用没问题，对外分发/商用前请自行复核数据授权。
- 已知限制：没有例句（`example` 恒为空）、音标是 ECDICT 旧式记法而非严格 IPA、释义是静态词义不结合语境、无中文释义的条目视为未命中回落大模型。字段映射细节见 [backend/README.md](../backend/README.md)。

## 导入 YouTube 播放列表为本地剧集

本地剧集以字幕与时间轴为主；能对应到 YouTube 视频的集会在导入时记下 `videoId`，从而复用视频播放器。把一个公开播放列表的英文字幕导入成本地剧集：

```bash
backend/venv/bin/python scripts/import_playlist.py --playlist-url "https://www.youtube.com/playlist?list=..."
```

- 用 yt-dlp 列播放列表（不下载视频），用 youtube-transcript-api 拉英文轨道，按播放列表顺序写入 `subtitles/<show_id>/S01/E01.srt`（`show_id` 默认由播放列表标题生成稳定 slug），并生成 `subtitles/<show_id>/meta.json`（`title` / `title_zh` / `thumbnail`，后端优先读它来显示标题与封面）。
- 同时写 `subtitles/<show_id>/episodes.json`：集 → 真实 YouTube `videoId` 的映射。每次运行都会按播放列表更新（与 SRT 是否已存在无关、幂等），有映射的集在 App 里可直接用「看视频」同款播放器，播放的就是对应 YouTube 视频；没有映射的集仍按纯字幕 + 模拟时间轴。
- 幂等：已存在的集自动跳过；单集失败只记录原因、不中断，最后打印汇总与处理建议。常用参数：`--limit N`（只导前 N 集）、`--show-id`（手动指定目录名）、`--force`（覆盖已有 SRT）、`--dry-run`（只看计划）。
- 只拉字幕，不翻译、不调用模型；在 App 里第一次打开某集时才走原有翻译链路（会产生模型费用）。
- 字幕是版权内容，仅供本机自用学习；`subtitles/` 已 gitignore，不会入库。

## 验证改动

- 前端：`cd frontend && npx tsc -b`（类型检查，作为提交门禁）+ `npx vite build`。
- 后端：`cd backend && venv/bin/python -m py_compile *.py`；离线测试 `cd backend && venv/bin/python -m pytest tests -q`。
- UI 改动：起开发服务器实际看效果，别只靠想象。
- **测试策略**：后端有离线 pytest 套件（`backend/tests/`，全部 monkeypatch 外部调用，不联网不花额度）；前端仍以 `tsc -b` + 浏览器实测为准。

## 规格驱动的工作流

参考 [spec-kit](https://github.com/github/spec-kit) 的方式管理。**较大的新功能**按这个顺序走：

1. **读宪法**：先看 [项目宪法](../CONSTITUTION.md)，确认方向不跑偏。
2. **写规格**：在 `specs/` 下新建 `00X-功能slug/spec.md`（用 [模板](../.specify/templates/spec-template.md)），只讲"做什么、为什么"。
3. **写方案**：复杂功能再写 `plan.md`（[模板](../.specify/templates/plan-template.md)），讲"怎么做"。
4. **拆任务**：必要时写 `tasks.md`（[模板](../.specify/templates/tasks-template.md)），逐项实现、逐项提交。
5. **实现 + 回填**：写代码，更新规格状态为"已实现"，补上对应代码路径。

小改动（改文案、修 bug、调样式）可直接做，不必走全流程。所有 UI 改动须符合 [设计语言](./设计语言.md)。

## 加一个新功能的清单

- [ ] 在 `specs/` 写 spec（复杂的再加 plan）
- [ ] 后端逻辑放进 `backend/` 对应模块（路由进 `routes_*.py`，核心逻辑进 `transcripts.py`/`translate.py`）；纯前端逻辑放 `frontend/src/lib/`，UI 放 `frontend/src/components/`
- [ ] 复用既有设计配方，不发明新样式
- [ ] 花钱/耗时的结果要落盘缓存（[宪法原则 4](../CONSTITUTION.md)）
- [ ] `tsc -b` 通过；UI 在浏览器里实测
- [ ] 更新相关文档

## 部署

本项目以本机自用为主，仓库不再内置部署配置（旧的 Dockerfile/railway/Procfile 已过时并删除，可从 git 历史找回参考）。若要部署：设好上面的安全环境变量（`API_AUTH_KEY`、`CORS_ORIGINS` 必设；HTTPS 下再设 `COOKIE_SECURE=1`）；把 `data/`（含 `app.db` 与 `users/`）和 `HISTORY_DIR` 指向持久卷，用户账号与各自的学习数据才不会丢。反向代理后如果所有请求同源，登录限流看到的是代理 IP，需要按实际拓扑调整或关闭限流。
