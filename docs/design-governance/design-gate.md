# 设计门禁（Design Gate）

> 版本：v0.1（2026-11-19）｜责任人：A5（质量门禁与 QA）｜审批：lead
> **状态：阶段 0 框架，未最终化。** 检查项是「可执行的占位」，数量、分级、路径清单与脚本接入方式，待 **A1 审计报告 + 阶段 1/2 规范（A2 令牌 / A3 交互导航）** 出来后定稿；阶段 3 才嵌入脚本与 CI。
> 本文不声称门禁已经落地。当前可执行的只有：PR 勾选（人工）+ 合并前 5 分钟走查 + 既有 CI（tsc / build）。

---

## 0. 一句话

UI 改动合并前，用 **7 个「是/否」问题 + 5 分钟走查** 兜住一致性——不加审批人、不加会议。

---

## 1. 触发条件

### 1.1 命中即触发（任一）

| 路径 / 变更 | 为什么触发 | 备注 |
|---|---|---|
| `frontend/src/components/**` | 全部用户可见组件 | 含 `.tsx` 与组件级样式 |
| `frontend/src/App.tsx`、`frontend/src/main.tsx` | 共享壳、路由挂载、全局状态 | 导航/子视图切换都从这里进 |
| `frontend/src/**/*.css` | 全局材质、焦点环、滚动条 | 含 `index.css` |
| `frontend/tailwind.config.*`、`frontend/postcss.config.*` | 令牌与构建链的单一来源 | 颜色/圆角/阴影/字体/缓动 |
| `frontend/src/i18n/*.json` | 用户可见文案 | `zh-CN` 为结构源，`vi-VN` 同步 |
| `frontend/index.html`、`frontend/public/manifest.webmanifest` | 文档壳、PWA 外观（标题/主题色/图标） | 改图标与主题色都算 |
| 共享壳 / 导航 / 布局 / 交互的等效改动 | 即使文件不在上面，只要改了用户看到的层级、跳转或操作方式 | 例：`frontend/src/lib/useNav.ts` 改返回行为 |

> 判定规则：**拿不准就按触发处理**。门禁只花 5 分钟，漏掉一次回归更贵。

### 1.2 不触发

- 纯后端（`backend/**`）、纯文档（`docs/**`、`specs/**`、`README*`）、`content/**` 静态数据、`scripts/**`、`.github/**`。
- 只改测试/类型定义、且不改用户可见输出。
- 依赖升级：除 `tailwindcss` / `postcss` / `react` / `framer-motion`（影响 UI 渲染或动效）外，**不触发**；以上四个按 1.1 处理。
- `mobile/**`（Expo 原生 app）：本轮不在治理范围（章程 §1），恢复跟进时另立规则。

### 1.3 本阶段不做

- 不做自动路径过滤 Action（不新增 CI 依赖）。
- 不在 repo 里新建 `.github/pull_request_template.md` 与脚本——片段与方案已写好（附录 A / §4.2），待 lead 确认后落盘，避免在规范未定前冻结检查项。

## 2. 检查项（7 项，是/否）

> 适用范围：触发了 §1.1 的 PR。每项只需回答「是 / 否」，并在 PR 里给证据（截图、命令输出或一句话说明）。**没有证据的勾选视为未通过。**

| # | 检查项（是 / 否） | 怎么判定（可验证的口径） | 不通过等级 | 依据 |
|---|---|---|---|---|
| **G1** | **令牌复用**：没有新增裸色值 / 魔法间距 / 新圆角档位；例外已注释并登记 | diff 里无新增 `#hex`、`rgb()`、`bg-[…]`、`p-[…]` 等设计语言未列出的任意值；颜色、圆角、阴影、玻璃材质优先用 `tailwind.config.js` 既有 token 与 `index.css` 的 `.glass-*`。设计语言明文规定的配方（如 `text-[17px]`、`text-[11px]`、`rounded-[10px]`、`tracking-[-0.015em]`）不算新增 | **P0**（新增语义色/间距且无注释） | 设计语言「颜色 / 几何 / 按钮 / 通用配方」；`tailwind.config.js` 的 `brand`/`glass`/`elev-*`/`ease-apple` |
| **G2** | **组件复用**：用现有组件或配方，没有复制出第二份实现 | 按钮 / 弹窗 / 分段控件 / 列表行 / 徽章 / 空态 / 关闭按钮直接复用配方或已有组件；新组件先在 `frontend/src/components/`（见其 README）找近似实现；确需新建 → 说明为什么不能复用 | **P1**；同一页面出现两套壳 / 两套弹窗行为不一致 → **P0** | `frontend/src/components/README.md`；设计语言配方；A4 映射表（阶段 2 后） |
| **G3** | **交互状态齐全**：hover / active / focus / disabled / loading 按需具备 | 新增或改动的可交互元素：列表行 hover 不缩放（靠背景/边框）；异步操作有 loading 与失败反馈；危险操作有确认；动效尊重 `prefers-reduced-motion` | **P1**；会导致重复提交（尤其计费流程）→ **P0** | 设计语言「动效 / 按钮」；AGENTS.md「UI 改动必须在浏览器实测」 |
| **G4** | **导航与返回**：符合 IA 规范，没有死路 | 入口/子视图符合《信息架构-导航重构》§7.3 返回矩阵与 §7.4 游客门禁；tab 切换不堆历史；子视图返回回到来源；深链/刷新可恢复；登录门禁在入口提示，不是进屏 403 白屏 | **P0**（死路 / 循环 / 403 白屏 / 刷新自动触发付费） | `docs/信息架构-导航重构.md` §7.2–§7.5；`lib/useNav.ts`、`lib/nav.ts` |
| **G5** | **端与状态覆盖**：桌面/移动实测，空/加载/错误态齐全 | 1440 与 375 两个宽度各截一张图；改导航壳必须加测 1024 / 768 断点；异步区域有空态、加载态、错误态；错误可重试或可退出；375 无横向溢出、底栏不遮挡主操作 | **P0**（375 阻断操作 / 白屏 / 横向溢出挡内容）；缺空态或加载骨架 → **P1** | 设计语言「空状态」；IA §6.4 遮挡防护；components/README 各屏声明 |
| **G6** | **可访问性**：键盘可达、焦点可见、对比度够 | Tab 能到达全部操作且有可见焦点（全局 `:focus-visible` 蓝环不被 `outline-none` 吃掉）；图标按钮有 `aria-label`/`title`；动态提示有 `aria-live`；正文与按钮文字对比度 ≥4.5:1（装饰性辅助文字按 3:1 或由 A2 裁定，记 P1） | **P0**（键盘无法完成主流程 / 焦点丢失）；其余 → **P1** | `frontend/src/index.css` 全局焦点环；设计语言「图标 / 动效」 |
| **G7** | **i18n**：文案走 `t()`，中越同步 | JSX 文本节点、`aria-label`、`placeholder`、toast 文案无硬编码中文/越南语；新增 key 同时写入 `zh-CN.json` 与 `vi-VN.json`；`{{placeholder}}` 一致；vi 无 CJK；`npm run check:i18n` 通过 | **P0**（只写一种语言 / check:i18n 失败 / vi 混入中文） | `specs/012` §5.7；`frontend/scripts/check-i18n.mjs`；IA §10.5 |

**不做成检查项的**：个人审美、动画时长微调、文案风格偏好——这些不阻断，记 PR 评论即可。

## 3. 等级与处置

| 等级 | 含义 | 处置 |
|---|---|---|
| **P0** | 阻断：用户走不通、走错、看到白屏/错语言，或同语义出现两套事实（两套色值/两套壳） | 修完再合并；不得靠「下次一起改」 |
| **P1** | 记录后修：可用但不一致（缺 disabled/加载、对比度不足、aria 缺失、动效未降级） | 合并前登记到 PR 描述，**7 天内**单独 PR 或随下个同类改动修完 |
| **P2**（可选） | 细节优化，不单独排期 | 只在 PR 评论里记一句，不计数 |

> 阶段 0 对**存量**问题不追溯（存量由 A1 审计出清单、A4 收敛处理）；门禁只拦「这次新引入/新改动的」。

## 4. 嵌入方式

### 4.1 PR 模板勾选（主入口）

改动命中 §1.1 时，PR 描述顶部粘贴附录 A 的勾选块；7 项全「是」或例外已登记，才可合并。评审者只需复核勾选与证据是否对得上，不重做走查。

### 4.2 CI（现状 + 阶段 3 计划）

| 门 | 现状 | 位置 | 阶段 3 计划 |
|---|---|---|---|
| 类型检查 | 已跑 `npx tsc -b` | `.github/workflows/ci.yml` → `frontend` job | 保持 |
| 构建 | 已跑 `npx vite build` | 同上 | 保持 |
| i18n | **脚本已有，CI 未接入** | `frontend/package.json` → `check:i18n` | 加一行 `npm run check:i18n`（改 CI，需 lead 同意） |
| 令牌扫描 | 无 | — | 可选 `check-design-tokens.mjs --diff`：只扫本次改动，避免存量债淹没新问题 |
| 可访问性冒烟 | 无 | — | 可选 Playwright 冒烟（`scripts/node_modules/playwright` 已有），只测壳与主路径 |
| Lint | 脚本已有，CI 未接入 | `package.json` → `lint` | 与本门禁无关，另行讨论 |

**边界**：阶段 0–2 不改 CI；门禁在 PR 层人工执行。脚本是「减少漏勾」的辅助，不是前置条件。

### 4.3 合并前 5 分钟走查（人工）

| 时间 | 动作 |
|---|---|
| 0:00–0:30 | 看 diff 范围：只碰了预期的文件？截图是否覆盖 1440 与 375？ |
| 0:30–2:00 | 1440 打开改动页，走完主路径**和**空 / 加载 / 错误（断网或清数据触发） |
| 2:00–3:00 | 375 重走同一路径：无横向滚动、底栏不挡主按钮 |
| 3:00–3:45 | 只用键盘：Tab 走完操作、Enter 触发、Esc 关弹窗；焦点始终可见 |
| 3:45–4:30 | 切 zh-CN ↔ vi-VN：文案不截断、不混语言；开 reduced-motion 看动效降级 |
| 4:30–5:00 | 返回 / 刷新 / 直接贴深链 URL：回到同一位置，不自动触发付费 |

证据随 PR：两张截图（1440、375）+ 一条命令输出（`tsc` / `build` / `check:i18n` 之一）。

### 4.4 与既有规则的关系

- 不替代 AGENTS.md 的提交门禁（`tsc -b`、后端 `py_compile`、浏览器实测），是叠加的「一致性」检查。
- 视觉配方以 `docs/设计语言.md` 为准；导航行为以 `docs/信息架构-导航重构.md` 为准；冲突时先修文档再改代码。
- 与 specs 的关系：功能行为正确性由对应 spec 验收，本门禁只管「做得一致」。

## 5. 例外 / 豁免

**什么时候可以例外**：设计语言没有覆盖的新材质/新场景；或复刻既有页面时不得不沿用旧值（应同时登记为 A4 收敛项）。

**登记格式**（必须可被搜索到）：

```ts
// design-exception: <原因> · <owner> · <YYYY-MM-DD> · <到期日或 issue 号>
```

```css
/* design-exception: <原因> · <owner> · <YYYY-MM-DD> · <到期日或 issue 号> */
```

- PR 勾选块里写明「例外数：N」，并附理由一行。
- **审批**：阶段 0–2 由 lead 批；阶段 3 后 lead 批、A5 登记。
- **时限**：≤30 天。到期未清 → 该文件之后的 UI 改动按 P0 复核（不再接受同类新例外）。
- **统计**：例外数计入 §8 指标 1；单周例外率（例外数 ÷ UI PR 数）> 20%，说明规范有缺口，反馈 A2 补规范。

## 7. 回滚

- **单个 PR**：直接 revert。UI 改动不得夹带不可回滚的数据迁移；若必须，拆 PR。
- **门禁误伤**：lead 在 PR 打 `design-gate-override` 标签并写一行理由后合并。同一检查项一周内误伤 ≥3 次 → 视为规则问题，由 A5 修订（而不是让大家继续绕过）。
- **规则回滚**：本文件的修改走 PR 并留变更记录；令牌/组件标准回滚由 A2/A4 决定，A5 不单方面改。
- **文档被误改**：`docs/design-governance/` 下文件均在版本控制内，按 git 回滚，禁止手工改历史结论。

## 8. 度量（每周一次，10 分钟内完成）

| 指标 | 定义 | 采集方式 | 目标（阶段 3 起） | 当前基线 |
|---|---|---|---|---|
| 每周新增硬编码 token 数 | 新增的裸色值 / 设计语言外任意间距-圆角值条数（含例外）÷ 该周 UI PR 数 | 阶段 0–2：PR 勾选块人工填「例外数」；阶段 3：`check-design-tokens.mjs` diff 输出 | 新增 = 0（例外全部登记） | 待 A1 审计提供存量基线 |
| 重复组件数 | A4 映射表中「同一语义存在多实现」的条目数 | `component-consolidation.md` 按周统计 | 每周不增；阶段 4 前下降 ≥50% | 待 A4（阶段 2） |
| 门禁通过率 | 首轮即 P0=0 且 7 项全勾的 UI PR ÷ 全部 UI PR | PR 模板 + 评审复核 | ≥ 90%；低于则复盘是「规范缺口」还是「误报」 | 阶段 3 起统计 |
| （诊断）例外率 | 例外数 ÷ UI PR 数 | 同上 | > 20% 触发规范补充 | — |

> 度量只用于发现规范缺口，不用于考核个人。周报不超过 5 行。
