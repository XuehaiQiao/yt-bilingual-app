# UI/UX 一致性治理 · 团队章程与阶段计划

> 版本：2026-11-19 ｜ 状态：阶段 0 进行中
> 目标：在正式上线前，把 UI/UX 从「各页面各自为政」变成一套可执行、可持续的规范，而不是一次大扫除。

## 1. 范围与技术栈

- 前端：React 19 + Vite 7 + Tailwind CSS 3.4 + framer-motion；组件为项目自定义，不使用 shadcn/ui。
- 范围：`frontend/src/` 下全部用户可见页面与共享组件、导航壳、阅读器、视频页、单词本、课程页、账户/设置、内容发现、博客、管理台。
- 不包含：后端接口语义重写、视觉品牌重塑、课程内容重构；自动生成课程功能**推迟到上线后**，本轮不投入。
- 产物目录：`docs/design-governance/`；组件与令牌规范放 `docs/design-governance/design-system/`。

## 2. 团队角色

| Agent | 职责 | 主要交付物 | 输入依赖 |
|---|---|---|---|
| **A1 现状审计员** | 盘点硬编码 token、重复组件、交互不一致、跳转异常、布局/信息层级问题；每条定位文件/页面并分级 | `audit-report.md` | 现有代码与页面 |
| **A2 设计系统架构师** | 从现有代码提取最小令牌集；定义核心组件清单、状态矩阵、布局栅格与层级原则 | `design-system/tokens.md`、`components.md`、`layout.md` | A1 报告 |
| **A3 交互与导航规范师** | 定义一致交互规则、页面层级模型、跳转矩阵、返回/面包屑规则 | `interaction-spec.md`、`navigation-model.md` | A1 报告 |
| **A4 组件复用工程师** | 将重复实现收敛到单一来源；给出旧实现→新组件映射与迁移步骤；优先重构高频组件 | `component-consolidation.md` + 重构代码/计划 | A2、A3 |
| **A5 质量门禁与 QA** | 设计轻量设计门禁（PR/合并前）与按模块的可勾选 QA 清单；嵌入现有 CI/PR 流程 | `design-gate.md`、`design-qa-checklist.md` | 阶段 1/2 产出 |

主协调：lead（拆解、门禁评审、最终 remediation-plan）。

## 3. 阶段与门禁

### 阶段 0：并行启动（A1 + A5 框架）

- A1：全量审计，覆盖用户列出的五类问题；每条问题可定位到文件/页面，按 P0/P1/P2 分级。
- A5：搭好 `design-gate.md` 与 `design-qa-checklist.md` 的框架（模块、触发条件、占位检查项），不写死未审计的细节。
- **门禁 0**：A1 报告覆盖五类问题且可定位；A5 框架与现有 CI/PR 兼容。lead 汇总后暂停，等待确认。

### 阶段 1：规范定义（A2 + A3 并行）

- A2：令牌优先从现有代码提取高频值，不凭空发明；组件只定义当前实际存在/即将需要的。
- A3：导航模型必须能解释现有全部页面跳转，并明确「哪些跳转需要修改」。
- **门禁 1**：A2/A3 逐条回应 A1 的 P0/P1 问题；不能覆盖的显式标「暂不处理」+ 理由。暂停等待确认。

### 阶段 2：组件收敛（A4）

- 基于 A2/A3 制定映射表；优先按钮、导航壳、单词卡、弹窗、阅读器控件等高频组件。
- **门禁 2**：映射表完整，每个旧实现有迁移步骤；不破坏现有功能。暂停等待确认。

### 阶段 3：门禁与 QA 落地（A5）

- 将规范转成可执行检查项；QA 按功能模块组织，全部是/否可勾选。
- **门禁 3**：QA 清单逐条对应审计问题类型；门禁嵌入 PR 流程。暂停等待确认。

### 阶段 4：交叉验证与修复计划

- 五个 Agent 交叉审阅；检查令牌覆盖、交互/组件冲突、QA 能否捕获审计典型问题。
- 产出 `remediation-plan.md`：P0/P1/P2 修复清单，区分「上线前必须」与「上线后迭代」。
- 最终验收四项：P0/P1 有规范/计划；令牌+组件覆盖 ≥80% UI；门禁已嵌入；QA 可逐条对应。

## 4. 工作原则

1. **务实优先于完备**：先解决高频、核心流程；不追求大而全的设计系统。
2. **规范可执行**：每条规范必须能变成代码约束或 QA 检查项；不写「应保持一致」这类空话。
3. **门禁轻量**：PR 模板几个勾选项 + 合并前快速走查，不做繁重审批。
4. **QA 防复发**：检查项直接对应审计发现的典型问题。
5. **单一来源**：颜色/间距/圆角/阴影/组件/交互，同一语义只允许一个来源。

## 5. 当前状态与下一步

- 阶段 0：A1 审计 + A5 框架进行中。
- 阶段 0 完成后由 lead 汇总门禁 0，**暂停等待用户确认**，再启动 A2/A3。
- 自动生成课程：功能已存在但不作为上线阻塞项；本轮不投入，课程重构报告作为上线后输入。
