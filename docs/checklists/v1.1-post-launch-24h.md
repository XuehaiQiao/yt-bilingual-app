## 7. 异常阈值（触发就升级处理）

| 指标 | 阈值 | 动作 |
|---|---|---|
| health 非 200 | 连续 2 次 | 立即查容器/DB |
| 5xx | >1% 持续 5 分钟 | 查日志；必要时回滚代码 |
| 登录失败 | 明显高于平时 | 查 auth/DB/ cookie |
| 找回密码失败 | >5% 或用户集中反馈 | 查 Resend/SMTP/链接域名 |
| 429 | 非预期集中 | 查额度单位/用户用量 |
| 磁盘 | >85% | 清日志/扩容；暂停非必要写入 |
| 备份失败 | 任意一次 | 立即补备份 + 离机 |
| DB integrity | 非 ok | 停止写入，按恢复流程 |

## 8. 回滚触发条件

满足任意一条，考虑回滚：

- 旧用户无法登录或数据丢失
- 迁移后出现持续 5xx / schema 错误
- 找回密码整体不可用且短时间修不好
- 数据库 integrity 失败

回滚顺序：

1. 先代码回滚：`IMAGE_TAG=41c463b docker compose up -d --force-recreate`
2. 仍不行：停服 → 数据库降级/整库恢复
3. 恢复后先 health + 旧账号 + 旧数据冒烟
