# 单词本缺少短语：问题分析与解决方案

> 版本：2026-11-17 ｜ 状态：后端已实现（前端/阅读标亮待做） ｜ 范围：单词本词表、阅读标亮、FSRS 复习

## 1. 问题不是“漏了几个短语”，而是数据模型只收单词

当前单词本的三个数据源都把「短语」排除在外：

| 来源 | 现状 | 为什么没有短语 |
|---|---|---|
| CEFR A1–C1 | `content/wordlist/frequency_bands.v1.json`，10,000 个 lemma | wordfreq 按单词频次生成，天然没有多词单位 |
| GRE / CET4 / CET6 | `content/wordlists/exam-bands.v1.json`，11,307 词 | 构建脚本 `WORD_RE = ^[A-Za-z]+$`，只收纯字母单词 |
| 单词本页面 | 单词行 + 词表查询 | API/UI 的条目类型只有 word，没有 phrase |

而 ECDICT 本身并不缺短语：`data/ecdict.db` 里 **366,599 条** 含空格的词条，带音标/中文释义。问题是：

1. 构建脚本把多词条目过滤掉了；
2. 精简 ECDICT 没有 `tag` 列，无法直接筛“CET4/6/GRE 短语”；
3. 即使有词条，也缺少「短语类型、CEFR、例句、是否非字面义」这些教学字段。

所以这不是补一个 tab 能解决的，需要**先补数据模型，再补内容与展示**。

## 2. 目标：什么样的短语值得进单词本

不是所有多词组合都值得背。建议只收三类，并设质量闸：

| 类型 | 例子 | 是否收 |
|---|---|---|
| 短语动词 | look after, give up, come across | ✅ 高频、非字面义优先 |
| 习语/固定搭配 | a waste of time, make up one's mind, on purpose | ✅ 高频、有语用价值 |
| 常见搭配 | heavy rain, make a decision | ⚠️ 只收高频且学习者常错的 |
| 普通从句/自由组合 | the big red house | ❌ 不收 |
| 专名/术语 | New York, quantum mechanics | ❌ 不收（除非考试词表明确收） |

质量闸（机器 + 人工）：

- 2–4 个词，归一化小写；不含专名/数字/标点；
- 必须有含中文的释义（ECDICT `translation` 或自建）；
- 至少包含一个动词/介词，或整体义 ≠ 字面义；
- 去重变体：`look after` / `look after sb.` 只留一个；
- 过滤过时/冒犯/政治敏感表达；
- 100 条人工抽检：释义、例句、CEFR、是否非字面义。

## 3. 四种候选方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 扩展现有 ECDICT 构建** | 允许多词条目；从完整 CSV 的 `tag` 列筛 CET4/6/GRE 短语；按 `frq/bnc` 排序 | 与现有词表同源、快；可复用释义 | 精简库无 tag；需重新下载 60MB CSV；tag 对短语的覆盖未知；许可风险同 ECDICT | **MVP 首选（先验证覆盖）** |
| **B. 自建 500–1,000 条教学短语表** | 从高频短语动词/习语清单人工整理，配释义/例句/CEFR | 质量可控、许可干净 | 人工成本 5–8 人日；需要教研 | **与 A 混合，用于补 A 的缺口** |
| **C. 从站内内容抽取** | 对 67 篇免费文章 + 公版书做 n-gram/POS/LLM 候选，人工筛 | 与用户实际阅读强相关；可直接用于阅读标亮 | 规模受内容限制；抽取噪声大；需要人审 | **第二阶段（内容短语）** |
| **D. 授权标准短语表** | 购买 Oxford Phrase List / OPAL 等 | 权威、CEFR 对齐 | 费用/许可谈判；不能立即上线 | 商业化后再考虑 |

**推荐：A + B 混合做 MVP**：先用 ECDICT 多词 tag 快速拿到 300–500 条，再用人工补 100–200 条高频习语/短语动词，总 500–1,000 条；C 作为第二阶段，让阅读中标亮「你正在读的文章里的短语」。

## 4. 数据模型

新增 `phrase` 条目，不混进现有 word 索引：

```json
{
  "headword": "look after",
  "kind": "phrase",
  "phraseType": "phrasal_verb",   // phrasal_verb | idiom | collocation
  "cefr": "A2",                    // 近似/人工标注；未知 C1+
  "phonetic": null,
  "translation": "照顾",
  "literal": "look + after",       // 可选：字面 vs 整体义
  "example": "She looks after her younger brother.",
  "source": "ECDICT",
  "license": "见 NOTICE",
  "rank": 1234
}
```

- 词表文件：`content/wordlists/phrases.v1.json`（与 exam-bands 同级）
- API：
  - `GET /api/vocabulary/lists/phrases?level=&type=&q=&page=&pageSize=`
  - `GET /api/vocabulary/phrases/{id}`（详情/例句）
  - `GET /api/vocabulary/level?phrases=a,b`（批量给 CEFR；或用 headword 查）
- 现有 word 表/API 不改；新增 phrase 类型，避免把「look after」塞进单词表。

## 5. UI

单词本增加一个 **「短语」** tab（放在「我的单词」之后、A1 之前）：

```
[我的单词 128] [短语 623] [A1] [A2] ... [GRE] [CET4] [CET6]

[搜索短语…]                    [中文 ● 显示 / ○ 隐藏]

look after        phr. v.  照顾        A2  ▾
give up           phr. v.  放弃        A2  ▾
a waste of time   idiom    浪费时间    B1  ▾
```

- 短语卡：headword + 类型 + 中文 + CEFR；展开显示例句、字面义/整体义、来源
- 隐藏中文：与单词一致，点短语临时显示
- 搜索支持 `look`、`after`、`look after`
- 「我的单词」也支持短语收藏（favorites `type: 'phrase'`；现有 vocabulary 行可复用）

## 6. 阅读标亮

短语标亮比单词难在**边界**：

- 用短语词典做 **最长匹配**（`look after` 优先于 `look` + `after`）；
- 同一段不重叠：先匹配短语，剩余单词再按单词表标亮；
- 只标「高于当前高亮档」的短语；未知短语按 C1+；
- 点击短语弹短语卡（不是单词卡）；
- 与现有左右双栏/点词/进度兼容。

建议第二阶段做：先把短语 tab 和词表做稳，再上多词匹配；否则容易一次改太多。

## 7. CEFR 怎么标

没有官方 CEFR 短语表，必须诚实：

1. **考试标签**（CET4/6/GRE）只说明考试范围，不等于 CEFR；
2. 用组成词的最高 CEFR + 短语频率做初判，再人工抽检；
3. 页面标「近似」；C2 仍无词表，不硬凑；
4. 对外不写「官方 CEFR 短语表」。

## 9. 风险

| 风险 | 处理 |
|---|---|
| ECDICT 数据许可（同现有词表） | NOTICE 续写；商用前法务复核或换授权源 |
| 短语 tag 覆盖不足 | 先跑 1,000 条样本验证；不足则 B 方案补 |
| 释义/例句质量 | 100 条人工抽检；不达标不进词表 |
| 多词匹配误标 | 最长匹配 + 不重叠 + 只标高一级；先不标短语，观察 |
| 短语与单词重复（give up vs give） | 词条类型分开；复习卡分开；去重键用 headword |
| CEFR 过度精确 | 标「近似」；C2 不提供 |

## 10. 建议的下一步

1. **先做数据验证**（1 天）：下载 ECDICT 完整 CSV，统计带 CET4/6/GRE tag 的多词条目数、释义覆盖率、100 条抽样质量。
2. 若覆盖 ≥300 条：按 A+B 做 MVP「短语」tab（500–1,000 条）。
3. 若覆盖不足：先人工整理 300 条高频短语动词/习语，再做 UI。
4. 阅读短语标亮放第二阶段；先保证词表与卡片正确。
