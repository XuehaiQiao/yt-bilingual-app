# 部署指南（LinguaTrek / 语途）

> 本文承接 [计划-上线部署.md](./计划-上线部署.md) 的 **M1 最小可用**清单，给出从零到上线的可执行命令。
> 项目默认仍是「本机自用」：这些文件只在部署时使用，不改变 `./start_app.command` / `npm run dev` 的本地开发方式。
>
> **两种上线方式，二选一：**
>
> | | 方式 A：Docker | 方式 B：VPS 裸机 |
> |---|---|---|
> | 适合 | 想要可复现、少装系统依赖 | 想直接控制进程、不装 Docker |
> | 前端静态 | 容器内由 `deploy/serve.py` 与 API 同进程服务 | Caddy 直接服务 `frontend/dist` |
> | API 进程 | 容器内 uvicorn（单 worker） | systemd + uvicorn（单 worker） |
> | 数据 | Docker 命名卷 `linguatrek-data` → `/data` | `/srv/ln/data` |
> | TLS/域名 | 宿主机 Caddy 反代 `127.0.0.1:8000` | 宿主机 Caddy 同域静态 + 反代 |
> | 备份 | `docker compose run` 调用 `scripts/backup.sh` | cron 调用同一脚本 |
> | 升级/回滚 | 镜像 tag | `releases/<stamp>` 符号链接 |
>
> 无论哪种方式，**同域、单写进程、SQLite WAL、每日离机备份** 这四条不变。

## 0. 先满足这些前提

1. **VPS 在海外**（新加坡 / 东京 / 美西 / 欧洲均可），2 vCPU / 4 GB 起步，Ubuntu 24.04。
   **不要用中国大陆机房**：YouTube 不可达，且涉及备案与合规问题（计划书 R10）。
2. 一个**域名**，能改 DNS 的 A 记录（Caddy 需要 80/443 自动签发证书）。
3. 至少一个模型 Key：`DEEPSEEK_API_KEY`（默认模型，大陆/海外都可直连）。
4. 本机（或 CI）能访问 GitHub 与 Docker Hub / npm / PyPI。VPS 只开 `22/80/443`。
5. **明确不设置** `API_AUTH_KEY`，**绝不设置** `VITE_API_KEY`（原因见 §2）。

### 0.1 基础系统（两种方式共用）

```bash
# 用有 sudo 权限的账号登录 VPS；以下命令逐段执行
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git rsync sqlite3 ufw ca-certificates cron rclone dnsutils openssl gpg

# 时区统一（影响日志与备份文件名；也可用 UTC，但要全机一致）
sudo timedatectl set-timezone Asia/Shanghai
timedatectl

# 防火墙：只放 SSH / HTTP / HTTPS
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

### 0.2 用户与目录（两种方式共用）

```bash
# 固定 UID 1000；若已被占用（部分云镜像有 ubuntu 用户），可换 UID，
# 但 Docker 若改用 bind mount 要注意容器内 UID 也是 1000（见 §3.7）。
id -u ln >/dev/null 2>&1 || sudo useradd --create-home --home-dir /srv/ln --shell /bin/bash --uid 1000 ln

sudo mkdir -p /srv/ln/releases /srv/ln/backups
sudo mkdir -p /srv/ln/data/history /srv/ln/data/subtitles /srv/ln/data/users /srv/ln/data/guests
sudo mkdir -p /srv/ln/data/home        # systemd 的 HOME（yt-dlp 等可能写缓存）
sudo chown -R ln:ln /srv/ln
sudo chmod 700 /srv/ln/data/users /srv/ln/data/guests /srv/ln/backups
# Caddy 以 caddy 用户读取静态文件，/srv/ln 必须可穿越
sudo chmod 755 /srv/ln /srv/ln/releases
```

### 0.3 安装 Caddy（两种方式共用；仅宿主机做 TLS）

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
caddy version   # 建议 >= 2.8
```

> 官方安装说明：<https://caddyserver.com/docs/install#debian-ubuntu-raspbian>。若系统已有 Caddy，可跳过。

### 0.4 域名与 DNS

在域名商处添加：

```
类型   名称   值
A      ln     你的 VPS IPv4
AAAA   ln     （有 IPv6 才填）
```

等待生效后用 `dig +short ln.example.com` 确认指向正确。Caddy 首次启动会自动申请证书；
若用 Cloudflare，**首次签发前先设为 DNS only（灰云）**，拿到证书后再决定是否开橙云。
Cloudflare 橙云默认 100s 空闲超时，SSE 必须已开启后端 15s 心跳（当前代码已默认开启）。

## 1. 上线前必须理解的三个数据事实

| 事实 | 含义 |
|---|---|
| 持久化只有 `data/` | `app.db`（用户 / 会话 / 迁移版本）+ `users/<id>/` + `guests/<hash>/` + `history/`。容器里是 `/data`，裸机是 `/srv/ln/data`。**卷丢了，账号和进度全丢。** |
| 数据库迁移由 Alembic 管 | 首次启动前必须 `alembic upgrade head`；否则事件、复习、任务等表不存在，相关功能降级/503。`/healthz` 会显示迁移版本。 |
| 单写进程 | SQLite + 进程内限流/缓存：uvicorn **只能 1 个 worker**，Compose 只能 1 个副本。不要 `scale`。 |

## 2. 必填 / 禁止的环境变量

> 模板：`deploy/linguatrek.env.example`。**真实值只放在服务器上的 env 文件里，权限 600，不提交。**

| 变量 | 生产值示例 | 说明 |
|---|---|---|
| `CORS_ORIGINS` | `https://ln.example.com` | **必填**。精确到前端来源，逗号分隔；禁止 `*`。同域部署通常一个值即可。 |
| `COOKIE_SECURE` | `1` | **HTTPS 必填**。`ln_session` Cookie 加 `Secure`。本地 HTTP 预览设 `0`。 |
| `ADMIN_EMAILS` | `you@example.com` | 推荐。管理员邮箱（`/api/admin/*` 止血台）；留空 = 没有管理员（全部 403）。 |
| `REGISTRATION_OPEN` | `false` | 默认关闭公开注册，新账号必须持邀请码（G1）；`true` 仅用于 G2。改完重启。 |
| `INVITE_SIGNUP_ENABLED` | `true` | 与 `REGISTRATION_OPEN=false` 同时为 `false` = 完全关闭新账号创建（登录不受影响）。 |
| `INVITE_CODE_PEPPER` | 随机长字符串（可选） | 邀请码 HMAC pepper；库里只存摘要。生产建议设置，轮换会让旧码全部失效。 |
| `DEFAULT_MODEL` | `deepseek-chat` | 必须在 `backend/config.py` 的 `MODEL_CATALOG` 中；非法值回落到 `deepseek-chat`。 |
| `DEEPSEEK_API_KEY` | `sk-...` | 中文路线主模型必填；**仅服务端**。 |
| `QWEN_API_KEY` | `sk-...` | 越南语目标必填（与 `QWEN_BASE_URL` 成对）；留空则 Qwen 不可用。 |
| `QWEN_BASE_URL` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | Qwen 端点；大陆站与国际站不同，**必须与 Key 同站**。 |
| `EVENTS_PSEUDONYM_SALT` | `openssl rand -hex 32` 的输出 | 生产必填：学习事件假名 HMAC 的盐；不设会用开发默认盐并告警。 |
| `VITE_API_BASE` | `https://ln.example.com` | **构建期必填**，不是运行时。改域名必须重新构建前端镜像。不带尾斜杠。 |
| `GEMINI_API_KEY` | 空 | 仅海外可选；大陆不可用/不合规，留空。 |

> 首次部署没有账号时：先临时 `REGISTRATION_OPEN=true` 注册管理员并设 `ADMIN_EMAILS`，随后改回 `false` 重启；或直接用 `auth_db` 创建管理员。不要长期保持公开注册。

### 2.1 绝对不要设置

| 变量 | 后果 |
|---|---|
| `API_AUTH_KEY` | `X-API-Key` 中间件覆盖**所有** `/api`（含 `/api/auth/login`）。浏览器登录会 401；把 Key 塞进前端 `VITE_API_KEY` 又等于公开密钥。**公网浏览器多用户部署必须留空。** |
| `VITE_API_KEY` | 会被打进 `frontend/dist`，所有访客可见，等于公开模型配额。 |
| `BROWSER_UI=0` | 只有「不提供浏览器界面、仅供移动端/内部客户端」时才设。 |

> 依据见 [计划-上线部署.md](./计划-上线部署.md) P0-3 与 `backend/config.py` 的启动警告。

## 3. 方式 A：Docker（推荐先跑通）

### 3.1 安装 Docker Engine

```bash
# 官方便捷脚本（执行前建议打开链接审阅内容）
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
sudo sh /tmp/get-docker.sh
sudo usermod -aG docker "$USER"   # 退出重新登录后生效
docker --version && docker compose version
```

> 不希望用便捷脚本时，按 <https://docs.docker.com/engine/install/ubuntu/> 的 apt 仓库步骤安装。

### 3.2 取代码

```bash
sudo mkdir -p /srv/ln/app
sudo chown ln:ln /srv/ln/app
sudo -u ln git clone https://github.com/huthvincent/yt-bilingual-app.git /srv/ln/app
cd /srv/ln/app
```

> 生产升级时固定 tag/commit：`git fetch && git checkout <tag>`，不要直接跟 `main`。

### 3.3 准备 env 文件

```bash
cd /srv/ln/app
cp deploy/linguatrek.env.example .env
chmod 600 .env
# 用你习惯的编辑器填入：CORS_ORIGINS / VITE_API_BASE / 域名 / Key / 盐
# 注意：VITE_API_BASE 必须是 https://你的域名，不能是 127.0.0.1
# 只做本机 HTTP 预览时，先把 COOKIE_SECURE 改成 0，否则浏览器不会回传 Secure Cookie。
${EDITOR:-vi} .env
```

确认关键项：

```bash
grep -E '^(CORS_ORIGINS|COOKIE_SECURE|VITE_API_BASE|DEFAULT_MODEL)=' .env
# 必须没有 API_AUTH_KEY / VITE_API_KEY：
grep -E '^(API_AUTH_KEY|VITE_API_KEY)=' .env && echo '❌ 删除这两行' || echo 'OK: 没有禁用的 key 变量'
```

> 直接用 `docker run` 时用 `--env-file .env` 注入这些变量；Compose 已在 `docker-compose.yml` 里配置 `env_file: .env`。

### 3.4 构建镜像与首次迁移

镜像里已经包含 `alembic` 与迁移脚本；Compose 的命名卷首次创建时会继承镜像 `/data` 的属主（UID 1000）。

```bash
cd /srv/ln/app
docker compose build           # 读取 .env 里的 VITE_API_BASE，写进前端 bundle
docker compose run --rm app alembic upgrade head
docker compose run --rm app alembic current    # 期望显示 0012_exam (head)
```

> 如果跳过了迁移直接 `up`，`/healthz` 仍可能 200（DB 文件可读即可），但事件/复习/任务等表不存在。
> **不要**对已有旧库直接 `alembic stamp head`；旧库升级见 `docs/开发指南.md` 的迁移一节。

### 3.5 启动

```bash
cd /srv/ln/app
docker compose up -d
docker compose ps              # STATUS 应为 Up (healthy)，首次等 30s 左右
docker compose logs -f app     # Ctrl-C 退出日志，不影响容器
```

容器内进程：`uvicorn serve:app`（单 worker）→ FastAPI + `frontend/dist` 静态文件；
`/healthz` 同时检查 DB 可读与迁移版本。端口只发布到宿主机 `127.0.0.1:8000`。

验证容器本身：

```bash
curl -fsS http://127.0.0.1:8000/healthz | python3 -m json.tool
# 期望 status=ok、db.ok=true、db.migrations.current=head
curl -fsS -o /dev/null -w 'index=%{http_code}\n' http://127.0.0.1:8000/
docker inspect --format '{{.State.Health.Status}}' "$(docker compose ps -q app)"
```

### 3.6 宿主机 Caddy（TLS 终止 + 反代）

Docker 镜像内部已经处理静态与 SPA fallback，宿主机 Caddy **只反代**，用 `deploy/Caddyfile.proxy`：

```bash
sudo cp /srv/ln/app/deploy/Caddyfile.proxy /etc/caddy/Caddyfile
sudoedit /etc/caddy/Caddyfile          # 把 ln.example.com 改成你的域名
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
sudo journalctl -u caddy -f            # 看证书签发/报错；Ctrl-C 退出
```

验证公网入口：

```bash
curl -fsS https://ln.example.com/healthz | python3 -m json.tool
curl -fsS -o /dev/null -w 'home=%{http_code}\n' https://ln.example.com/
curl -fsSI https://ln.example.com/ | grep -i -E 'strict-transport-security|content-security-policy'
```

### 3.7 数据卷与权限

默认使用命名卷 `linguatrek-data`，**不需要**手工 chown。只有改成 bind mount 时才需要：

```yaml
# 示例：docker-compose.yml 中把
#   - linguatrek-data:/data
# 改成
#   - /srv/ln/data:/data
```

并在宿主机执行：

```bash
sudo chown -R 1000:1000 /srv/ln/data    # 容器内 ln 的 UID
```

否则容器启动会报 `ERROR: 数据目录不可写`（`deploy/entrypoint.sh` 的前置检查）。

### 3.8 Docker 方式的备份 / 恢复

备份文件放宿主机 `/srv/ln/backups`，由同一个 `scripts/backup.sh` 生成（含 `app.db` 一致性快照 + `users/` + 校验和）：

```bash
sudo mkdir -p /srv/ln/backups
sudo chown 1000:1000 /srv/ln/backups

cd /srv/ln/app
docker compose run --rm --no-deps \
  -v /srv/ln/backups:/backups \
  -v "$PWD/scripts:/scripts:ro" \
  -e BACKUP_ROOT=/backups \
  -e ENV_FILE=/dev/null \
  --entrypoint /bin/bash \
  app /scripts/backup.sh --keep 7

ls -lh /srv/ln/backups
```

加入宿主机 cron（备份脚本本身保留 7 份；离机用 rclone）：

```bash
sudo crontab -e
# 每天 03:17；日志 /var/log/linguatrek-backup.log
17 3 * * * cd /srv/ln/app && docker compose run --rm --no-deps -v /srv/ln/backups:/backups -v /srv/ln/app/scripts:/scripts:ro -e BACKUP_ROOT=/backups -e ENV_FILE=/dev/null --entrypoint /bin/bash app /scripts/backup.sh --keep 7 >> /var/log/linguatrek-backup.log 2>&1
# 03:25 离机（先 sudo rclone config 配好 remote，例：r2:linguatrek-backup）
25 3 * * * rclone copy /srv/ln/backups r2:linguatrek-backup/daily --include "linguatrek-backup-*.tar.gz" --checksum --transfers 2 >> /var/log/linguatrek-rclone.log 2>&1
```

恢复（先停服务；脚本会校验 SHA256 + `integrity_check`，`--force` 把旧数据移到 `/data/.pre-restore-*`）：

```bash
cd /srv/ln/app
docker compose stop app
docker compose run --rm --no-deps \
  -v /srv/ln/backups:/backups \
  -v "$PWD/scripts:/scripts:ro" \
  --entrypoint /bin/bash \
  app /scripts/restore.sh /backups/linguatrek-backup-YYYYmmdd-HHMMSS.tar.gz --to /data --force
docker compose start app
curl -fsS http://127.0.0.1:8000/healthz | python3 -m json.tool
```

### 3.9 Docker 方式的升级与回滚

`docker-compose.yml` 用 `linguatrek:${IMAGE_TAG:-latest}` 打标签。部署新版本：

```bash
cd /srv/ln/app
git fetch && git checkout <tag>
export IMAGE_TAG=$(git rev-parse --short HEAD)
docker compose build
docker compose run --rm app alembic upgrade head    # 先备份！见 §5
docker compose up -d
```

回滚到上一个镜像（数据库迁移不回滚，必要时按 §5 恢复备份）：

```bash
docker images 'linguatrek:*'                       # 找到旧 tag
IMAGE_TAG=<旧tag> docker compose up -d --no-build
docker compose logs --tail=100 app
```

> 迁移是向前兼容的（只加表/加列），代码回滚通常不需要动库；若迁移已破坏数据，
> 停服 → 用最近备份恢复 → 再用旧镜像启动。**数据库永远先备份再迁移。**

## 4. 方式 B：VPS 裸机（systemd + Caddy）

### 4.1 安装 Python / Node / 工具

```bash
sudo apt install -y python3.12 python3.12-venv python3-pip sqlite3 rsync rclone
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
python3.12 --version && node --version
```

> Node 只用于在服务器上构建前端。不想在 VPS 装 Node，也可以在本机构建好
> `frontend/dist` 后 `rsync` 上传（见 4.7），服务器只保留 Python 运行。
> Caddy 安装见 §0.3。

### 4.2 发布一个 release

```bash
STAMP=$(date -u +%Y%m%dT%H%M)
sudo -u ln git clone https://github.com/huthvincent/yt-bilingual-app.git /srv/ln/releases/$STAMP
# venv 放在每个 release 内，回滚时依赖跟着 release 一起回退
sudo -u ln python3.12 -m venv /srv/ln/releases/$STAMP/venv
sudo -u ln /srv/ln/releases/$STAMP/venv/bin/pip install --upgrade pip
sudo -u ln /srv/ln/releases/$STAMP/venv/bin/pip install -r /srv/ln/releases/$STAMP/backend/requirements.txt

# 构建前端（VITE_API_BASE 必须显式传，构建期写死）
sudo -u ln bash -lc "cd /srv/ln/releases/$STAMP/frontend && \
  VITE_API_BASE=https://ln.example.com npm ci && \
  VITE_API_BASE=https://ln.example.com npm run build"

sudo ln -sfn /srv/ln/releases/$STAMP /srv/ln/current
# Caddy 需要能读静态文件
sudo chmod -R a+rX /srv/ln/releases/$STAMP/frontend/dist
```

> venv 在 release 内，回滚时随符号链接一起回退；不要把所有 release 共用一个 venv，
> 否则升级依赖会连带影响仍在运行的旧版本。发布目录保留最近 2–3 个，回滚靠切符号链接。

### 4.3 环境变量文件

```bash
sudo install -d -m 750 -o root -g ln /etc/linguatrek
sudo install -m 600 -o ln -g ln /dev/null /etc/linguatrek/env
sudo -u ln vi /etc/linguatrek/env
```

写入（按实际替换；**不要写 API_AUTH_KEY**）：

```ini
# ---- 站点/安全 ----
CORS_ORIGINS=https://ln.example.com
COOKIE_SECURE=1
ADMIN_EMAILS=you@example.com

# ---- 模型 ----
DEFAULT_MODEL=deepseek-chat
DEEPSEEK_API_KEY=<...>
QWEN_API_KEY=<...>
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
EVENTS_PSEUDONYM_SALT=<openssl rand -hex 32 的输出>

# ---- 路径（裸机映射；全部绝对路径） ----
DATA_DIR=/srv/ln/data
AUTH_DB_PATH=/srv/ln/data/app.db
USER_DATA_DIR=/srv/ln/data/users
GUEST_DATA_DIR=/srv/ln/data/guests
HISTORY_DIR=/srv/ln/data/history
SUBTITLES_DIR=/srv/ln/subtitles
SENTENCES_DIR=/srv/ln/current/content/sentences
PLACEMENT_DIR=/srv/ln/current/content/placement
EXAM_DIR=/srv/ln/current/content/exam
CURATED_CONTENT_PATH=/srv/ln/current/content/curated.json
BLOG_DIR=/srv/ln/current/content/blog
LOCAL_DICT_PATH=/srv/ln/data/ecdict.db

# ---- 可选 ----
APP_VERSION=2026.11.15
# GEMINI_API_KEY=     # 仅海外
```

```bash
sudo chown ln:ln /etc/linguatrek/env
sudo chmod 600 /etc/linguatrek/env
# 确认没有禁用项
sudo grep -E '^(API_AUTH_KEY|VITE_API_KEY)=' /etc/linguatrek/env && echo '❌ 删除' || echo 'OK'
```

> `/etc/linguatrek/env` 是 systemd `EnvironmentFile`，**不要**把同名 `.env` 放到发布目录让应用自己读；
> 两者都读会让人误判最终值。容器方式才使用 Compose 的 `.env`。

### 4.4 首次迁移

```bash
sudo -u ln bash -lc 'set -a; . /etc/linguatrek/env; set +a; \
  cd /srv/ln/current/backend && /srv/ln/current/venv/bin/alembic upgrade head'
sudo -u ln bash -lc 'set -a; . /etc/linguatrek/env; set +a; \
  cd /srv/ln/current/backend && /srv/ln/current/venv/bin/alembic current'
# 期望 0012_exam (head)
```

### 4.5 安装并启动 systemd 服务

```bash
sudo cp /srv/ln/current/deploy/linguatrek.service /etc/systemd/system/linguatrek.service
sudo systemctl daemon-reload
```

## 5. 备份、恢复与离机副本（两种方式通用纪律）

### 5.1 每日备份

裸机（systemd）：安装仓库里的 cron 文件：

```bash
sudo mkdir -p /srv/ln/backups && sudo chown ln:ln /srv/ln/backups
sudo install -m 644 /srv/ln/current/deploy/backup.cron /etc/cron.d/linguatrek-backup
# 先手工跑一次（以 ln 身份，复现 cron 的权限）
sudo -u ln bash -lc 'cd /srv/ln/current && \
  DATA_DIR=/srv/ln/data AUTH_DB_PATH=/srv/ln/data/app.db USER_DATA_DIR=/srv/ln/data/users \
  BACKUP_ROOT=/srv/ln/backups ENV_FILE=/etc/linguatrek/env \
  /srv/ln/current/scripts/backup.sh --keep 7'
sudo tail -n 30 /srv/ln/backups/backup.log
ls -lh /srv/ln/backups | tail
```

Docker：见 §3.8。两种方式都会得到 `linguatrek-backup-YYYYmmdd-HHMMSS.tar.gz`，
包含 `app.db`、`users/`、`manifest.env`、`SHA256SUMS` 与配置**键名**（不含密钥值），默认保留 7 份。

**离机副本（必做）**：在 rclone 配好远端后，把 `/srv/ln/backups` 同步到 R2/B2/S3（示例见 `deploy/backup.cron` 注释与 §3.8 的 crontab）。本机备份只防误删，不防 VPS 磁盘/机房故障。

### 5.2 恢复演练（上线前与每月各一次）

脚本会先校验 `SHA256SUMS` 与 `PRAGMA integrity_check`，全部通过才写入目标目录，
并默认拒绝非空目标；`--force` 会把旧的 `app.db` / `users/` / `backup-meta/` 移到 `.pre-restore-*`。

```bash
# 1) 自动演练：备份 → 临时恢复 → 与源数据比对（不碰真实 data/、不占端口）
sudo -u ln bash -lc 'DATA_DIR=/srv/ln/data AUTH_DB_PATH=/srv/ln/data/app.db \
  USER_DATA_DIR=/srv/ln/data/users /srv/ln/current/scripts/restore_drill.sh'
# 期望最后一行：PASS 恢复演练通过：...

# 2) 真实恢复（先停服务，确认备份文件时间点）
sudo systemctl stop linguatrek
sudo -u ln bash -lc '/srv/ln/current/scripts/restore.sh \
  /srv/ln/backups/linguatrek-backup-YYYYmmdd-HHMMSS.tar.gz --to /srv/ln/data --force'
sudo systemctl start linguatrek
curl -fsS http://127.0.0.1:8000/healthz | python3 -m json.tool
sudo -u ln sqlite3 /srv/ln/data/app.db 'PRAGMA integrity_check;'   # 期望 ok

# 3) 确认恢复后能登录旧账号、历史仍在；确认无异常后再清理 .pre-restore-*
```

Docker 恢复命令见 §3.8（同样先 `stop app`，恢复后再 `start`）。

### 5.3 备份检查清单

- [ ] 第一次备份已成功，文件大小非 0，`manifest.env` 里 `DB_SHA256` 有值
- [ ] `restore_drill.sh` 输出 PASS
- [ ] 对象存储里能看到当天文件（`rclone lsf r2:linguatrek-backup/daily | tail`）
- [ ] 备份目录权限 700，且 `backup.log` 没有“警告：未找到 sqlite3”之类降级提示
- [ ] 每月做一次真实恢复演练并记录结果

## 7. 常见故障

| 现象 | 先查 | 处置 |
|---|---|---|
| 502 / 页面打不开 | `systemctl status linguatrek`；`docker compose ps`；`curl 127.0.0.1:8000/healthz` | 进程没起、端口不匹配、Caddy 反代地址错；看 journald / `docker compose logs` |
| `/healthz` 返回 503 `degraded` | 响应里的 `db.ok`；`ls -l /data/app.db` / `/srv/ln/data/app.db` | DB 文件不存在/不可读 → 跑 `alembic upgrade head`；权限不对 → 按 §3.7 修 |
| `migrations.current` 不是 head | `alembic current` / `head` | 先备份，再 `alembic upgrade head` |
| 登录成功但刷新后又回登录页 | 是否 HTTPS；`COOKIE_SECURE=1`；CORS 是否精确；`Set-Cookie` 是否有 Secure | 本地 HTTP 预览设 `COOKIE_SECURE=0`；公网必须 HTTPS；同域部署 |
| 登录 401 且日志有 API Key 提示 | 是否设了 `API_AUTH_KEY` | 删除该变量并重启；**浏览器部署永远不设** |
| SSE 60/100s 就断 | Caddy 是否 `flush_interval -1`；是否走了 Cloudflare 橙云 | 用 `deploy/Caddyfile(.proxy)`；Cloudflare 先灰云或确认心跳 |
| 一个用户开流后全站卡 | 是否多 worker/多副本；是否 `LLM_MAX_CONCURRENCY` 太大 | 保持 1 worker / 1 副本；调低并发；看 `journalctl` |
| `database is locked` | 是否多进程写；是否有长事务 | 单写进程；备份/迁移在停服或低峰做；不要 scale |
| `ERROR: 数据目录不可写`（Docker） | §3.7 | 命名卷通常自动正确；bind mount 执行 `chown 1000:1000` |
| Caddy 证书签发失败 | 80/443 是否放行；DNS 是否指向本机；Cloudflare 代理 | `journalctl -u caddy`；先灰云；确认 A 记录 |
| 磁盘满 | `df -h /data` / `df -h /srv/ln`；`du -sh /srv/ln/data/users/*` | 清理旧缓存/旧 release；扩卷；先备份再删 |
| 备份失败 | `/srv/ln/backups/backup.log`；`command -v sqlite3` | 安装 sqlite3；检查目录属主与空间；手动重跑一次 |
| YouTube 429 / 抓取失败 | 服务器出口 IP 是否被限；日志 `IpBlocked` | 降低频率、换出口、稍后重试；不要无限重试 |

## 10. 与计划书的关系 / 边界

- 本文只覆盖 **M1 最小可用**（一个域名、HTTPS、同域、单机、可备份可回滚）。
- 注册开关已在应用层落地（M1 G1，specs/032）：`REGISTRATION_OPEN=false`（默认）
  时公开注册关闭，新账号必须持邀请码；管理员在后台「邀请码」页生成/撤销。
  M2 的其余多用户加固（账号维度限流、越权验收、Sentry、配额）仍按
  [计划-上线部署.md](./计划-上线部署.md) §4 执行；M6 的 Caddy Basic Auth 仍属部署层，
  不替代应用内邀请码。
- Docker 镜像内**不运行数据库容器**；SQLite 与 `/data` 卷同位，TLS 由宿主机 Caddy 负责。
  这样只有两个进程概念（uvicorn + Caddy），排查面最小。
- 任何情况下都不要把 `.env`、`data/`、`history/`、`subtitles/` 提交或打进镜像；
  不要为了“方便”关闭 `COOKIE_SECURE` 或设置 `API_AUTH_KEY`。
