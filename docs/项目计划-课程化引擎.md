## 0. 一页结论（给负责人）

### 0.1 命题一句话

**把一段真实内容变成一堂 12 分钟的课：1 个可检验的目标、5 个锚定原文的教学点、8 个可判分检查（+1 道不计分的整体理解检查）、1 次产出、4 个词进 FSRS；同一段内容对 A2 学员与 B1 学员是两套窗口/选点/题目/产出，但共享同一条字幕缓存、同一套题目管线、同一套复习调度。**

### 0.2 差异化：不是“AI 讲课”，是“选 / 限 / 检 / 回 / 复”

| 能力 | 现状（翻译工具） | 课程化之后 | 竞品为什么难抄 |
|---|---|---|---|
| **选** | 整片翻译，用户自己找重点 | 规则+模型从内容里选出 3.5 分钟“最值得教”的窗口 | 需要用户自己的内容缓存与时间轴 |
| **限** | 逐句高亮，15 分钟视频 100+ 个高亮 | 每课只教 **4 个词 + 1 个形式/语用点**，其余只“点”不“讲” | 是教学法约束，不是模型能力 |
| **检** | 看后 3 道理解题（真实数据：0 次作答） | 6+2 个检查，全部挂回目标与证据块 | 需要“块身份 ↔ 题目证据”的稳定对齐 |
| **回** | 答错可回跳（已有） | 每个讲解点/每道题都能回到那一秒（±0.3s）或那一段 | 需要双语时间轴 + 播放器 seek + 模态中立定位符 |
| **复** | FSRS 生词本（已有） | 课内 4 词自动入队；形式点下节课 1 题回收；次日 + 第 7 天 60 秒回访卡 | 需要 per-user 词状态与调度 |

> **讲解不是护城河**。讲解的边际成本已趋近 0，竞品一周能抄；而且**讲解越多，越说明“选、限、检、回、复”没做**。这是本计划与“AI 老师讲 8 分钟”方案的根本分歧。

### 0.3 MVP 定义（7–8 周，可上线验证）

| 项 | MVP 规格（v1） | 理由 |
|---|---|---|
| 课长 | **12 分钟**，但形态是**分段交错**：3 段 ×（观看 70s + 讲解 33s + 2 题 40s），视频课合计 **12:24**、文章课 **11:45**、移动 **11:12** | 真实数据只有“最活跃账户单日 11.5 分钟（剔除 600s smoke 后 11.65）”；**12 分钟是当前最合理的起点，不是“唯一有数据依据的上限”**——它是待验证的产品假设（E-C4 同时测 8/12/15 分钟） |
| 内容单位 | 视频 **3.5–4.2 分钟 / 550–730 词**（块数 35–50 只作渲染提示）；A2 **2–2.5 分钟 / 300–430 词**；文章 **250–350 词 / 2–3 段**（现有 3 篇 269/323/269 词则整篇一课） | 库内视频按块跨度 159–183 wpm；3.5–4 分钟只能装 557–732 词，“45–55 块 = 600–800 词”三者互相打架。**只有“时长 + 词数”双约束成立，块数不能当约束** |
| 首发内容 | **3 篇自有文章公课**（A2/B1/B2，共 861 词，整篇一课）+ **用户自带内容私课**（10–20 名种子用户，视频或文章） | 第三方视频（BBC/TED-Ed/Kurzgesagt）不能做公课；861 词是唯一零版权库存 |
| 教学点 | **4 个词 + 1 个形式/语用点**（形式库匹配不到时降为 4 点课并明说）；文化点私课 0、公课 1 条人工策展卡；词源永久 0；背景用“上下文定位卡”（1 句原文，0 幻觉） | 12 分钟课最多承载 5–7 个点；每多 1 点 ≈ 多 90 秒讲解 + 多 1 个检索落点 |
| 练习 | **6 道主测 + 2 道离场测 + 1 道不计分 gist**：basic 细节 2/因果 1/词义 2/形式 1；core 细节 2/词义 2/形式 1/推断 1；advanced 细节 1/词义 2/形式 1/推断或语用 2；**只用 mcq/tf** | 现有 `questions` 的 CHECK 只允许这两种；听写/填空要重建表（约 2 人日），MVP 不值；basic 加 1 道因果题是为了让“为什么危险”这个目标有对应检查 |
| 产出 | 写 **2–5 句 / 20–90 词（按档）**（A2 20–40、B1 40–60、B2 60–90）；**不打分**，给 3 项 rubric + 1 条改写对照 + 确定性统计 | 与“不报分/不提分”的既有硬边界一致；LLM 打分“自信的错分”比不给更伤信任 |
| 复习 | 课内 **4 词**自动入 `word_states`，**计入当日 `new_limit=10`**（不是叠加）；形式点不进 FSRS，下节课暖场 1 题回收；**S5 出口 + 次日 / 第 7 天 60 秒回访卡** | 8 课/月 = 32 词/月 = 容量 10.7%；用 8 个会到 21%，挤掉用户在别处遇到的词 |
| 生成 | **4 次 LLM 调用**（分析 / 选点+词表 / 出题+产出任务 / 产出反馈）**+ 1 次 T1 交叉复核**；异步 job；p50 **60–90 秒**、p95 ≤150 秒；单课输出 ≤**4,200 token**（硬顶 5,000） | 8.8k 输出要在 12–18 秒出完需要 489–733 tok/s，没有可用模型能做到；必须异步。5 点×3 档 + 8 题 + 范文的实测预算约 4.2–5.3k，3,050 是低估 |
| 公课人审 | **100%**（9 个 pack 预生成：3 篇 × 3 档；**按难度矩阵只开放 5 个有效 + 1 个实验**；主档 30–35 分钟，变体 10–15 分钟） | 模板不成熟、首通率未知；公课要签字；预生成数量不能冒充库存 |
| 私课人审 | **0% 人工 + T1 全量模型复核 + 2% 抽检 + 100% 举报处理**；UI 标“AI 生成，未经人工审核” | 私域、不公开、不跨用户；但私课是视频主路径，8 道机械闸只证明“引文真”，不证明“讲得对” |
| 数据 | **4 张新表**；教学点/步骤进 `payload_json`，题目落 `questions` 为单一真源 | 全站版权干净库存只有 861 词；建 6 张表是过度设计，但 items 双写必须收口 |
| 接口 | `/api/course/*`；**不重命名**现有 `/api/lesson/*`（理解题） | 改名换 0 用户价值，却动 3 个前端文件 + 16 个测试 |
| 事件 | **7 个**：`course_open / course_stage_complete / course_word_check / course_answer / course_output_submit / course_complete / course_too_hard` | 事件不可回填，必须一次定稿 |
| 人日 | **80–93 人日**（v0.1 基线 54–64 + 评审修订增量 26–29；+15% 缓冲 **92–107**）；2.9 FTE 下 **7–8 周**；1.5 FTE 下 **12–14 周**（或砍范围到 54–64，9–10 周） | 前端仍是最大单项（12–14 人日）；增量主要来自覆盖率闸、数据生命周期、视频 spike + locator、私课 T1、双主终点评测 |
| 单课成本 | **账本口径 ≤$0.0162/课**（≈¥0.115，含 15% 重试 + T1 + 产出反馈）；**真实口径约 $0.0065–0.0081**（¥0.046–0.057） | v0.1 的 $0.0118 是按 3,050 输出 token 算的，实际要约 4,200；见 §9.2 |
| 不做 | 25/30/45 分钟课、文化百科、词源、口语/写作评分、6 档 CEFR、每用户一份讲稿、第三方视频公课、vi 讲解、离线/PWA、课程地图、教师市场、新闻课、考试课 | 见 §1.4、附录 A |

### 0.4 单课成本与单位经济（一句话）

**AI 生成 ≤$0.0122/课（账本口径），含 15% 重试 + T1 复核 + 一次产出反馈 ≤$0.0162（约 ¥0.115），真实口径约 $0.0065–0.0081（¥0.046–0.057）；公课全成本 ¥120/节（90 分钟人审+编辑+发布），是 AI 成本的约 1,000 倍（单审 ¥40–47 约 350–410 倍）；私课边际 ¥0.1–0.2/节。** 成本不是主要风险，人审供给才是。

### 0.5 两个闸门：G0 内容质量（W1）与 G1 意愿（W2）

v0.1 把“M0 离线 spike”当成“证伪用户愿不愿意上课”，但离线 spike 里**没有用户**——它的能力是“证内容质量”，不是“证意愿”。v1 拆成两个闸，顺序执行：

**G0 内容质量闸（W1，7–8 人日，离线，无 UI）**：跑 5 条内容 × 2 个难度档（共 10 个 pack），全量跑第 1–9 道闸。过闸条件：

1. 引文存在率 **100%**（每条 quote 都是原文归一化子串，时间点落在块内）；
2. 覆盖率闸对每个档给出数字，并**拒绝**不达标的组合（例如 Kurzgesagt 的 A2 版必须被拒）；
3. 两位评审（教研 + 负责人）各盲评**至少 20 个讲解点 + 10 道题 + 5 个产出任务**（不是只看 10 个点），**≥16/20 个讲解点“可以原样给用户看”、≥8/10 道题“答案可证且无歧义”**；
4. 单课输出 **≤4,200 token**、账本成本 **≤$0.0162**、端到端 ≤120 秒；
5. 至少 1 位评审说“我愿意让我的学生上这堂课”。

**G1 意愿闸（W2 末，10 人 concierge，真 go/no-go）**：手动为 10 个真实用户各做 1 节课（可用 G0 的 pack + 人工编排），观察：**6/10 走完主体、5/10 愿意上第二节、3/10 提交产出**。不过就**重设模板或停**，不写课程 UI。

> G0 与 C-M1 地基的关系（M7 修订）：地基 25–29 人日**预批准、可复用**（W2–W3 做，与 G1 的 concierge 并行，但 G0 单独占 W1）；G0/G1 失败只停“管线扩写 + 课程 UI”，不退地基。v0.1 的“不过就停”改成 **“不过就不扩”**——因为地基一旦开工就是沉没成本，“停”拦不住它，“不扩”才拦得住。

### 0.6 主要风险（前五条）

| # | 风险 | 为什么是它 | 早期信号 |
|---|---|---|---|
| R1 | **用户不愿在看完内容后上课** | 现有“看后 3 题”在真实数据里 **0 次作答**；我们要在这个没被验证的交互上加五层 | G1 6/10 未达成；入口曝光→开始 <25%；首课完成 <35%；“太麻烦”反馈 >30% |
| R2 | **版权/衍生作品** | 课 = 译文+讲解+题目+文化评论，比字幕缓存更像“作品”；一条投诉可能让公课库整体下架 | 公课来源无台账；用户导入含他人音乐/画面；举报涉版权 |
| R3 | **教研供给与招聘 lead time** | 人审是 AI 的约 1,000 倍；能判断“语法解释对不对”的人不是普通标注员；招聘 4–8 周 | 首通率 <60%；审稿队列 >20 节；κ <0.6；审校月流失 >20% |
| R4 | **讲解幻觉/语法错误** | 引文闸只证明“引用真实”，不证明“讲得对”；文化/百科卡连引文闸都过不了 | 讲解错误率 >1/100 点；举报率 >2%；用户说“这里讲错了” |
| R5 | **评测效度与对外话术** | 完课率/答题正确率会被当成“学会了”；n<100 时任何“有效”都是讲故事 | 市场要求写“提分/达 B2”；团队拿段末正确率当效果证据 |

> 第六到第十八条见 §11.1。**范围膨胀**是执行层最大的隐性风险，用“阶段分钟和 ≤12:30”“S3 讲解 ≤16%”“主动 ≥45%”三条机械校验挡住（§2.2）。

### 0.7 需要现在拍板的 6 件事

1. **批准 G0（7–8 人日，W1）+ G1（W2，10 人 concierge）**：G1 是 go/no-go，不过就不扩。

## 1. 从翻译工具到课程引擎：价值与不做什么

### 1.1 现状证据：我们有一个很好的“内容缓存 + 3 题”底座，但没有“课”

| 事实 | 实测（2026-11-16，本机） | 对课程化的含义 |
|---|---|---|
| 真实使用 | 7 个注册用户 + 游客共 **12 个账户**、**45 条**观看事件、合计 **28.2 分钟**（其中 1 条 600 秒 `smoke-video` 是测试，**剔除后 18.2 分钟**）；最活跃账户单日 **11.5 分钟（原始 21.65 分钟，剔除 smoke 后 11.65）** | 没有任何证据支持 25–30 分钟课；12 分钟是唯一有数据依据的起点，但仍属弱先验（n=12） |
| 理解题 | `questions` **0 行**、`attempts` **0 行** | “看后 3 题”从未被做过一次；课程化要复用它当练习阶段，但它的产品验证度是 0 |
| 生词本 | `word_states` **1 行** | FSRS 地基在，但“课内 4 词入队”是新增行为，必须校准配额 |
| 内容库存 | 3 条第三方视频（BBC/TED-Ed/Kurzgesagt，license 写明版权归频道所有）+ 3 篇原创文章（269/323/269 词，license “原创，免费使用”） | **唯一零版权公课库存 = 861 词**；第三方视频只能私课/嵌入 |
| 字幕规模 | 本机 Bloomberg 缓存 **125 块 / 1,683 词 / 10.0 分钟**；库内视频 77/61/110 块，1,005/1,040/1,578 词，**块跨度 159.3/183.2/164.6 wpm（duration 口径 159.1/171.4/159.9）** | 窗口必须按“时长+词数”双约束切；只按块数会切出 1.6–2.1 倍词量 |
| 词频 | ECDICT **770,611 行 / 6 列**（`word/sw/phonetic/definition/translation/exchange`），**无** `bnc/frq/collins/oxford/tag` | 没有频率列就没有可靠的“i”；补 6 列是分级地基（约 2 人日，离线零 LLM） |
| 成本账本 | `MODEL_CATALOG` 只有 `gemini-2.5-flash` 有价（0.30/2.50）；DeepSeek/Qwen 全 `None`，账本按“已知最贵”记 | 所有成本报表当前高估约 1.7×；填价目是 1 行配置，但不填所有预算判断都是错的 |
| 内容模型 | `content_items` 无 `license`/`derivative_policy`；`kind CHECK IN ('video','local_show')`；`questions` 只允许 `mcq/tf`；`/api/lesson/*` 已被“3 道理解题”占用 | “公课”在系统层现在无法阻止；新引擎必须另立 `content_catalog` 与 `/api/course/*` |
| 测试 | 553 个离线测试（仓库口径；本机 462 个 `def test_`，parametrize 展开约 550+） | 增量必须保持全绿；新增 70–90 个课程测试 |
| 画像 | `user_profiles` 实为 `cefr / level_band_low / level_band_high / vocab_estimate(int) / reading_estimate(CEFR) / confidence`，**没有** `vocab_band`/`reading_band` | 分级映射必须按真实字段写：`vocab_estimate → 词数带 → i`，`reading_estimate` 作上限，**不能把“词数”和“CEFR 带”直接取 min**（量纲不同） |

**一句话**：现有系统完成了“课的原料”（双语块、译文、题目闸、证据回跳、FSRS、画像、周报、jobs、账本），缺的是“课的结构”（选段、选点、分级、编排、产出、质检）。这不是重写底座，而是加一层可选的“教学壳”。

### 1.2 课程化的三层价值

| 层 | 翻译工具给不了 | 课程化给什么 | 复用现有 |
|---|---|---|---|
| 内容层 | 整片内容难度不可调 | **选窗口 + 选点**：同一内容对不同档切不同长度、不同词、不同脚手架 | `history/*.json` 块、文章段落、ECDICT、画像 |
| 任务层 | 看完就结束 | **目标 + 讲解 + 练习 + 反馈 + 产出**：一节课有起点、有终点、有交付物 | `questions`/`attempts`、`QuizScreen` 判分与证据回跳 |
| 连续层 | 词进生词本，但课与课不衔接 | **形式点下节课回收 + 4 词 FSRS + 7 天回访卡 + 课次进周报事实句** | `srs.py`、`reports.py`、`learning_events` |
| 商业层 | “翻译 + 查词”无法支撑订阅 | 付费理由是“有人替你把这段内容备成一节课”，不是“翻译得更准” | 现有账号/余额/后台 |

### 1.3 护城河：五件事，恰好都长在现有地基上

| # | 能力 | 现有地基 | 课程化要补的 |
|---|---|---|---|
| 1 | **选**：哪 3.5 分钟值得教 | `history` 双语块 + 时长/句块结构 | `backend/course/segment.py`（规则，0 LLM） |
| 2 | **限**：每课只教 4 词 + 1 形式 | 词汇轴 `config.VOCAB_LEVELS` + 模板 | 候选池 + 硬上限 + 打分 |
| 3 | **检**：每个点当场检索、答错回跳 | `questions.evidence_start/end` + `QuizScreen` 回跳 | 目标↔检查双向对齐 |
| 4 | **回**：错题回到原声那一秒 | 播放器 seek + 字幕时间轴 | 模态中立 `locator`（视频=seek，文章=滚到段/句） |
| 5 | **复**：词进 FSRS、形式点下节课 | `word_states` + `review_logs` + `word_sources` | 4 词配额 + 下节课暖场 1 题 + 7 天回访卡 |

> **讲解只是这五件事的外壳。** 如果一节课里“讲解 + 呈现”超过总时长的 28%，说明我们在用“讲”掩盖“没选对、没限住、没检到、没回跳、没复习”。

### 1.4 明确不做（写进 spec 的“不做清单”，防止反复重提）

| 不做 | 触发条件/备注 |
|---|---|
| 整片视频 = 一堂课 | 永不；一条 60 分钟视频 = 12–15 节课，懒生成 |
| 25 / 30 / 35 / 45 分钟课 | MVP/V1 都不进路线；数据支持后可复议（E-C4 只测 8/12/15） |
| 文化百科/历史/宗教/政治背景 | MVP 0；公课 1 条人工策展 `language_culture` 卡；百科要 URL + 人审，V1 |
| 词源（etymology） | 永久禁（幻觉不可逆、教学回报最低） |
| 口语评分、写作评分、发音分 | 与“不报分”红线冲突；说留 V1 且本地录音、不打分 |
| 6 档 CEFR × 每用户独立生成 | 三档措辞一次生成 + 规则裁剪；成本差 3–5 倍 |
| 课程目录/章节/学期/证书/等级解锁 | 是内容运营问题，不是引擎问题 |
| 教师市场、直播 1v1、人工反馈包月 | V2+；人工按次卖，不进订阅 |
| 新闻课、考试课/真题 | 版权 + 时效 + 事实核查；现有自编考试练习独立保留 |
| 第三方视频公课、UGC 公课 | 拿到书面许可 + 审核人力前一律禁止 |
| 离线/PWA/锁屏播放 | 计划书已定不做；通勤文案删掉 |
| 越南语讲解 | MVP 不做（`target_lang=vi` 回落到中文讲解 + UI 说明）；找到 vi 审校后 V1 |
| AI 对话陪练、生成音视频、AI 模仿名人声音 | 永不（本计划范围内） |
| 课程地图/自适应学习路径 | 20 节/用户数据 + 效度验证后再做 |
| 排名、打卡、XP、徽章墙 | 反游戏化清单已冻结 |
| 学习质量综合分、“学习指数” | 永久禁 |
| 段中途弹题（深度课例外） | 段末暂停已是打断，段中再插题会让 12 分钟变成 20 分钟（§6.4） |

## 2. 课程模型

### 2.1 单位：可教窗口（teachable window）

**不是视频、不是句子、不是段落，而是“一个完整的交际动作”**：一段叙事节拍、一步论证、一个操作步骤。判据是“看完这一段，学习者能回答一个完整的问题”。

| 对象 | 范围 | 说明 |
|---|---|---|
| 句块（block） | 1 句，5–16 词，约 3–7 秒 | 现有 `history` 单位，证据锚点；`start/end` 是**秒（float）**，入库统一 ×1000 转 ms |
| **视频窗口（core/B1）** | **3.5–4.2 分钟 / 550–730 词**；块数 35–50 只作渲染提示 | 3.5–4.2 分钟 × 159–183 wpm = 557–768 词，故上限取 730 |
| **视频窗口（basic/A2）** | **2–2.5 分钟 / 300–430 词**；块数 20–30 | 另需 wpm ≤150 且覆盖率达标（§3.8） |
| **视频窗口（advanced/B2–C1）** | **4–4.5 分钟 / 650–770 词**；块数 40–55 | 164.6 wpm × 4–4.5 = 658–741 词 |
| **文章窗口** | **整篇一课**：现有 3 篇 269/323/269 词（6 段），课程内按 3 段读（每段约 90–110 词） | 250–350 词 / 2–3 段只在“自写新文章”时作为写作目标；现有文章 2–3 段只有 66–162 词，凑不够一课，**不能按段切** |
| 一堂课 | **12 分钟**（MVP，分段交错）/ 15 分钟（V1） | 视频 12:24、文章 11:45、移动 11:12（§2.2） |
| 一条 10 分钟视频 | 2–3 节课 | 懒生成，不预生成整片 |
| 一条 60 分钟视频 | 12–15 节课 | 课程地图只显示窗口与时间，不生成 |

**窗口选择（规则，0 LLM）**：先硬约束，再打分。

- 硬约束：起止落在句块边界；首块是完整句；末块有句末标点；窗口不跨“换场”（相邻块间隔 ≥2.5 秒视为换场）；**时长与词数同时落在档位范围内**（两个约束都要过，块数不看）；覆盖率达档位门槛（§3.8）。
- 打分（0–1 加权）：`0.25×时长贴合 + 0.15×边界完整 + 0.15×场景连续 + 0.15×主题词复现 + 0.20×可教点密度 + 0.10×UTR 接近目标带`。
- **先规则，后模型**。切分错误会毁掉整堂课；规则错误可复现、可修。MVP 不做 LLM 选段（V1 才对 >15 分钟内容做 outline 推荐）。

**同模板的文章变体（现有 3 篇公课）**：S0 0.5 + S1 1.75 + 3 段 ×（读 60 秒 + 讲解 30 秒 + 2 题 40 秒 = 130 秒）+ S5 3.0 = **11.75 分钟（11:45）**。阅读时长按 90–110 wpm 算（90 词 ≈ 60 秒），不是视频口径的 4 分钟。

#### 2.2.1 时间盒算术（v1 自己先过，再写进模板）

| 校验 | 定义（可机械计算） | 视频课 | 文章课 | 门槛 | 判定 |
|---|---|---|---|---|---|
| 阶段分钟和 | S0–S5 相加 | **12.40** | **11.75** | ≤12.5（12:30） | ✅ |
| 主动分钟 | “猜义 + 作答 + 写 + 自评”之和：S0 0.33 + S1 1.00 + S2–S4 2.00 + S5 2.50 = 5.83 | **5.83（47.0%）** | 5.83（49.6%） | ≥45%（≥5.6 分钟） | ✅ |
| S3 段末讲解 | 3 段 × 33 秒 = 99 秒；**不含 S1** | **1.65（13.3%）** | 1.50（12.8%） | ≤16% | ✅ |
| S1 呈现 | 4 词 × 11 秒揭示/例句/发音 = 44 秒（猜义的 60 秒算主动，不算讲授） | **0.73（5.9%）** | 0.73（6.2%） | ≤15% | ✅ |
| 直接讲授合计 | S1 呈现 + S3 讲解 = 0.73 + 1.65 | **2.38（19.2%）** | 2.23（19.0%） | ≤28%（且满足 v0.1 的“讲解 ≤20%”） | ✅ |
| 原声/阅读输入 | S2 观看或阅读 | **3.50（28.2%）** | 3.00（25.5%） | ≥25% | ✅ |
| 每段题量 | S4 题数 / 段数 | 2 / 段 | 2 / 段 | 主测合计 6 | ✅ |

> **口径修正（必须写进 spec，否则校验无法执行）**：v0.1 的“讲解 ≤20%”没有定义是否含 S1。按旧时间盒算：含 S1 是 3.5 分钟 = **29%（不过）**，不含 S1 是 2.0 分钟 = **16.7%（过）**——同一条硬校验，两种答案。而“主动 ≥50%（≥6 分钟）”按旧 stage 表上限只有 **5.5 分钟**（S1 1.5 + S4 2.0 + S5 2.0），**根本算不出来**。
>
> v1 把它拆成三条可分别断言的规则：**S3 讲解 ≤16%**、**S1 呈现（揭示/例句/发音）≤15%**、**主动（猜义/作答/写/自评）≥45%**，并把“S1 + S3 ≤28%”作为总闸。重构后四个数分别是 13.3% / 5.9% / 47.0% / 19.2%，**无论含不含 S1 都过**；但口径必须写清，否则 CI 不知道断言哪个数。
>
> **为什么不硬凑 50%**：12.5 分钟课时里，3.5 分钟原声 + 0.73 分钟词卡呈现 + 1.65 分钟段末讲解 + 约 0.5 分钟范文/收束 + 0.2 分钟读目标，被动时间下限已约 6.58 分钟，**主动时间物理上限约 5.92 分钟**；要凑到 6 分钟只能砍窗口或砍预教，而这两项正是命题核心。**如实写 45%，并在 E-C4 里同时测 8/12/15 分钟的主动时间占比**，比继续写一个做不到的 50% 更诚实。

#### 2.2.2 三条硬校验进 CI（不是建议）

`backend/tests/test_course_template.py` 必须断言：

1. 模板各阶段分钟和 ≤ 12.5（含文章变体 ≤ 12.5）；
2. 按“猜义/作答/写/自评”口径重算的主动分钟 ≥ 0.45 × 总分钟；
3. S3 讲解 ≤ 0.16 × 总分钟，且 S1 呈现 + S3 讲解 ≤ 0.28 × 总分钟。

任一条不过 → `test` 红 → 不许发布模板。**模板改一次就跑一次**；这也是防止“每加一个阶段课就变 25 分钟”的唯一机制。

### 2.3 用户要的 8 个元素 → 落在哪（不缩水，但也不硬塞）

| 用户要的 | 落在哪 | MVP 怎么做 | V1 补什么 |
|---|---|---|---|
| **暖场** | S0 | 上节课形式点 1 题（无则跳过）；S1 的“先猜”本身也是暖场 | 自适应暖场（按到期词/错题选） |
| **背景介绍** | S2 开头 | **上下文定位卡**：1 句原文（前/后 2 个窗口）+ ≤20 字改述“这段在讲什么”；不含任何外部知识，可机械校验 | 百科背景卡（必须带 URL + 人审） |
| **词汇** | S1 + S3 | 4 个目标词；2 个 `produce`（产出必用）、2 个 `practice`；都进 FSRS | 词族/搭配扩展（按需） |
| **精听/精读** | S2 | 3.5 分钟窗口（3 段 ×70 秒）+ 1 道不计分 gist；单句循环/倍速复用现有播放器 | 精听片段 2 个 ×30–45 秒 |
| **语法** | S3 | **1 个形式点，来自 60–100 条人工形式库**：pack 存 `form_id` + 人工 `explain_template`，LLM 只写 `why_here`（≤40 字，必须引用本句），T1 校验；匹配不到就 4 点课并明说 | 2 个形式点（15 分钟课） |
| **俚语/文化** | S3 | 1 个语用/俚语点（来自 150 条人工词表，可为 0）；文化点私课 0、公课 1 条人工策展卡 | 文化 `language_culture` 1 条（AI 生成 + 人审） |
| **输出** | S5 | 写 3–5 句 / 40–60 词（basic 20–40、advanced 60–90）；不打分；3 项 rubric + 1 条改写对照 + 确定性统计 | 说（本地录音自评）、7 天后再产出 |
| **复习** | S5 + 下节课 + 次日 | 4 词 FSRS（计入 `new_limit`）+ 2 道离场测 + 下节课暖场 1 题 + **次日 60 秒回访卡**（到期词 + 上节课 1 个形式点） | `item_reviews`（形式点 7/30 天调度）+ 产出复习 |

> **口径**：MVP 的“文化”是一张卡，不是一个阶段；“背景”是一句原文定位，不是百科；“俚语”是人工词表里选 1 条，不是模型自由生成；“语法”是人工模板 + 一句“为什么用在这”，不是模型自由写。这四条是用户要求与成本/幻觉风险的交点，不能含糊。

### 2.4 目标：1 条主目标 + 2 条支撑目标，且必须可检

采用“can-do + 证据 + 条件”三段式；学习者看到一句人话，**不出现 CEFR 代码**。

- 主目标（任务型，1 条）：`看完这段 3.5 分钟的访谈，你能用自己的话说明“为什么他的感受和经济数据不一致”，并给出 2 个理由。`
- 支撑目标（2 条）：`能用出本课 4 个目标词中的至少 2 个。` / `能在表达“一边…一边…”时用出 as / while 从句。`
- **硬对齐**：每条目标 ≥1 个检查项；每个检查项挂回一条目标；没有检查的目标删掉，没有目标的检查删掉。课末离场测是目标的抽样验收。
- 目标不超过 3 条。第 4 条一定意味着这课太满。
- **因果类目标必须配因果题**：v0.1 的 A2 目标写了“为什么危险”，但 6 道题与产出框架里都没有“为什么”——这是“目标↔检查硬对齐”在自己的例子里就失败。v1 规定：目标里出现 `为什么/原因` → 主测必须含 1 道因果题（`role=causal`），产出框架必须给 `because` 句式。basic 档的 6 题因此是 **细节 2 / 因果 1 / 词义 2 / 形式 1**。

### 2.5 产出：课与视频的分水岭

| 档 | 任务 | 长度 | 反馈形态 |
|---|---|---|---|
| **basic（A2）** | 抄一句 + 换一个词（把证据句里的 X 换成你自己的生活）+ `because` 补一个原因 | 20–40 词 / 3–5 句 | 只判“换了没有 + 语法对错”，1 行 |
| **core（B1）** | 用 2 个目标词复述这一段 | 40–60 词 | 1 行点评 + 1 个改写对照 |
| **advanced（B2–C1）** | 用 3 个目标词说明/反驳一个观点 | 60–90 词 | 1 行点评 + 1 个更地道的表达 |

- **不打分、不算 CEFR、不给百分比、不出红叉**；只给：任务完成（0/1/2）、目标语言使用（0/1/2）、可读性（0/1/2），**总分不展示**。
- 确定性统计：用了几个目标词、多少词、是否用了形式点；这些零成本且诚实。
- **1 次重写**（提交后可改一次，不重复计分）→ 落成 **`revision` 0/1 两行**，初稿与初版反馈不覆盖（§5.2.3）。
- 范文由人工/审核过的模板提供，不让模型自由写“标准答案”。
- 产出是“课”与“看视频”最本质的分水岭：**没有交付物就不算上完**。

### 2.6 复习与跨课衔接（不新增 SRS 基础设施）

- **词**：每课自动入 4 个目标词（不是 8 个）；`srs.add_word` 幂等；`word_sources` 记录来源句 + `course_id`（去重条件含 course，见 §5.2.3）。
- **形式点**：不进 `word_states`（会污染 lemma 调度）；服务器按 `user_id + 最近 3 课` 选 1 题放在下节课 S0；间隔天然 1–3 天。**次日回访卡再回收 1 次**（把 v0.1 的“只回收 1 次”补成 2 次）。
- **内容理解**：不单独复习；错题进周报证据（复用 specs/015 的 evidence 机制）。
- **到期词回收**：若复习队列有到期词，离场测的词义题可换成“到期词 3 选 1”；没有则不换。**课不抢复习队列的位置，只做补充**。
- **7 天 60 秒回访卡（E2）**：首页一张卡“60 秒复习这课：4 个到期词 + 1 个上节课形式点”。复用 `routes_review` 的到期队列与 `ReviewScreen`，**不新增表/调度器**；点击记 `course_open{entry:"review_card"}`，不加第 8 个事件。
- **已知缺口（MVP 承认）**：形式点长期保持未验证；产出没有复习。V1 加 `item_reviews`（复用 FSRS 算法，约 1.5 人日）+ 7 天后同内容“再产出”（0.5 人日 + 1 个模板）。

### 2.7 失败与降级（课是可选层，不是新门槛）

| 情况 | 降级 |
|---|---|
| 生成超时/失败 | 回到自由观看，提示“这节课稍后可在课程页继续”，不阻断；重试走 jobs；失败不计配额（`refund`） |
| 窗口太难（离场测 <50% 或 `too_hard` 连续 3 次） | 提示“换短一点的窗口” + 自动降一档重建（同内容不同 `band_group` 可复用缓存，但**会重新调用 points/items，20–40 秒**） |
| 整体理解失败（gist 错） | 不阻断；给 1 次“回看段首”提示，gist 落 `attempts(role=gist)` 但不计入 6+2 |
| 用户没时间 | “只做 3 分钟版”：看 1 段（70 秒）+ 2 道题；输出与形式点留到下次 |
| 内容无字幕/双语不全 | 不上课；沿用现有 ASR/翻译流程完成后才出现“精讲”入口 |
| 敏感内容命中 | 不生成课，只保留翻译/查词；一句话提示，不解释理由 |
| 形式库匹配不到 | 4 点课 + UI 说“本节无语法点”，不要模型自由写 |
| 模型/配额不可用 | 429 文案区分“课程额度”与“复习/查词不受影响”；回退自由观看 |
| 覆盖率不达标 | 不开该档（basic 尤其常见）；提示“换短一点的窗口”或降一档；不静默放宽门槛 |

### 2.8 七条硬规则（防“讲解很多但学不会”）

1. **讲授预算**：S3 讲解 ≤16%（≤2.0 分钟）、S1 呈现 ≤15%（≤1.9 分钟）、两者合计 ≤28%（≤3.5 分钟）。超过就删，不是压缩。
2. **先做后讲**：每个点先让学习者猜/答/判断，再揭示解释；没有尝试的讲解不进课。
3. **3+1 规则**：一课最多 3 类新信息（4 词、1 形式、0–1 文化）+ 1 个输出任务；多出来的进下节课。
4. **无检索不教学**：任何新点必须在今天（段末 2 题 / 离场测）或 24 小时内（FSRS / 下节课回收 / 次日回访卡）被检索一次；没有复习落点的点直接删。
5. **一屏 ≤3 行、每行 ≤60 字、术语 ≤1 个/课**；说“这句为什么用 as”，不说“时间状语从句”。
6. **解释只在证据上**：每条讲解挂 `locator`（视频含 `start_ms`，文章含段落/句）；挂不上的解释不许出现（文化补充卡单独标注）。
7. **让“讲太多”在数据上疼**：离场测 <2/3 或某阶段流失 >40% → 标 `too_hard`，下次自动减 1 词、减 1 题；连续 3 次 → 人工复核。

### 3.1 CEFR → `band_group` → `i`（含输入覆盖率门槛）

| `band_group` | 对外 CEFR | 内部 `i`（词汇轴） | 视频窗口（时长 / 词数） | 输入覆盖率门槛 | 目标词 | 形式/语用 | 题量 | 产出 | 脚手架 |
|---|---|---|---|---|---|---|---|---|---|
| **basic** | A2（A1 不上真实内容课） | 3k | 2–2.5 分钟 / 300–430 词（块数 20–30 仅渲染提示） | 未知 token ≤3%、未知 lemma ≤8/100 词；**视频另需 wpm ≤150** | 4（高频具体词 + 语块） | 1 个形式（高频句型/时态） | 6+2+1gist（细节 2 / 因果 1 / 词义 2 / 形式 1） | 20–40 词 | 双语字幕常显；可回放 |
| **core** | B1 | 5k | 3.5–4.2 分钟 / 550–730 词（块数 35–50） | 未知 token ≤5%、≤12/100 词 | 4（含短语动词） | 1 个形式（时态/从句/连接）或 1 个俚语 | 6+2+1（细节 2 / 词义 2 / 形式 1 / 推断 1） | 40–60 词 | 英文字幕；整句中文可点开 |
| **advanced** | B2–C1 | 8k–12k | 4–4.5 分钟 / 650–770 词（块数 40–55） | 未知 token ≤8%、≤18/100 词 | 4（搭配/语域/低频） | 1 个形式（非谓语/虚拟/衔接）或 1 个俚语 | 6+2+1（细节 1 / 词义 2 / 形式 1 / 推断或语用 2） | 60–90 词 | 英文字幕；中文只在点词/点句 |

- **`i` 的来源（按真实字段重写）**：`user_profiles.vocab_estimate`（int，词数）→ 词数带：`<3k → A2/3k`、`3k–5k → B1/5k`、`5k–8k → B2/8k`、`≥8k → C1/12k`，取该带下限为 `i`；`reading_estimate`（CEFR）换算成同档 `i` 作**上限**；`i = min(词数带推出 i, 阅读档推出 i)`——**两个都是词数才可比较**，v0.1 写“`min(vocab_band, reading_band) − 0.5`”是量纲错误（一个是词数，一个是 CEFR 带），必须改。
- `level_band_low/high` 只用于 UI 显示“按你的 B1 裁（估计，±1 档）”，不参与计算。
- **三档措辞只在同一候选池内共享**：一次 `points` 调用对每个点输出 `basic/core/advanced` 三版措辞；**候选池与窗口随 band 变**，所以跨档是不同产物（键含 `band_group`，§4.7）。切档成本：同窗口换措辞 <1 秒、0 成本；换窗口 **20–40 秒 + ≈$0.0033**。v0.1 写的“切档 0 成本 <1s”只在第一种情形成立。
- **不显示“B1.3”**：对外只说“按你的 B1 裁”；结果页标注“难度是估计，不是考试分数”。
- **听力不按阅读档位推**：定位测没有听力题；用“脚手架默认值 + 用户切换”代替推断（A2 双语、B1 英文+整句中文、B2+ 英文+点词）。
- **同一内容可对不同档开不同窗口**：`band_group` 是“这一课”的难度，不是“这篇内容”的永久标签。B2 内容的 basic 版必须过覆盖率闸（§3.8）；做不到就不开 basic 版（宁缺毋滥）。
- `known_lemmas`（从 `review_logs` 派生：≥2 次正确跨 ≥2 日）：现只有 `(user_id, reviewed_at)` 索引，按 lemma 扫描会慢——MVP **加索引** `(user_id, lemma, rating, reviewed_at)`（若 lemma 不在 `review_logs`，先在写入路径冗余该列），不做 24h 物化。

### 3.2 选段策略（视频 / 文章）

**视频**：

1. 按句块边界切成候选窗口（步长 10–15 块，重叠 5 块）。
2. 过滤：**时长或词数不在档位范围**；首块非完整句；末块无句末标点；跨换场（gap ≥2.5s）；覆盖率达不到档位门槛。
3. 打分：`0.25 时长 + 0.15 边界 + 0.15 场景 + 0.15 主题复现 + 0.20 可教点密度 + 0.10 UTR 接近`。
4. 取 top 1；用户可“换一段”（显示 2–3 个候选窗口，不预生成内容）。
5. 选段不调 LLM；`outline`（长内容推荐段）V1 再做。

**文章**：

1. **整篇一课**：现有 3 篇 269/323/269 词各 1 课；课程内按 2 段合并成 3 个阅读段（每段约 90–110 词）。
2. 段落可作“背景/主旨”，但窗口必须包含至少 1 个可教点密度高的段落。
3. 不跨标题/小标题边界；不选纯引用/纯列表段。
4. 自写新文章（V1，600–800 词）才按 250–350 词 / 2–3 段切窗口。
5. 文章证据用 `locator{kind:'article', paragraph_index, sentence_index, quote}`，**没有 `start_ms`**（§5.1、§5.4）。

### 3.3 抽什么、抽多少（直接回答“词汇/语法/俚语/文化”）

| 类型 | 每课**选** | 候选池 | 规则 | 明确不做 |
|---|---|---|---|---|
| **词汇** | **4** | 25–40 | band > i；频率带 2k–10k；窗口内复现 ≥2 次或阻断理解；有词族/搭配价值；非专名/缩写；排除 `known_lemmas` 与 `word_states` | hapax、纯学术术语、拼写变体、只出现一次的专名 |
| **语法/形式** | **1** | 5–8 | 在 **60–100 条人工形式库**内（`form_id` + CEFR + regex + 2 个人工例句）；本段有清晰例证；`pattern` 命中证据句；级别匹配。**LLM 只写 `why_here`，不写语法解释** | 大纲外、需要 3 句以上才能讲清、纯术语辨析 |
| **俚语/语用** | **1（可为 0）** | 3–6 | 命中 150 条人工词表；`register` 可标注；非敏感；有 attestation | AI 自行猜测的习语、网络新词（只 `mention`，不进练习/产出）、侮辱/涉性/涉毒 |
| **文化** | 私课 **0**；公课 **1**（人工策展） | 1–3 | 仅 `language_culture`（语域/褒贬/地域/代际/字面 vs 引申）；公课由编辑写，标注“补充，非原文” | 词源、百科、宗教/政治/历史断言、无来源文化点 |
| **背景** | **1 条上下文定位卡** | 前后 2 个窗口 | 1 句原文 + ≤20 字改述；可机械校验；不含外部知识 | 百科背景（V1 且必须 URL + 人审） |
| **发音/连读** | 0（MVP） | 2–5 | 连读、弱读、重音影响理解；V1 做 | 系统音标课、逐词纠音 |
| **篇章/立场** | 0（MVP） | 2–4 | B2+ 的连接词、hedging、评价性形容词；V1 | 学术写作课 |

- **总计 5 个讲点**（4 词 + 1 形式/语用），不是 CL 的 11–20 个。11–20 个只有在 28–40 分钟课里才成立。
- **4 词是教学上限，不是覆盖保证**：600 词窗口里未知词可能 30–60 个，预教 4 个覆盖不了——所以必须有 §3.8 的覆盖率闸，否则就是“翻译辅助解码”冒充可理解输入。
- **候选池不进表**：`payload_json` 里存 `candidates`（25–40 条）+ `points`（5 条）；跨课复用/查询触发拆表（>500 课）。
- **选点打分**：`0.40×unknown + 0.30×utility + 0.20×teachable + 0.10×anchor`；硬约束先于打分（≤4 词、≤1 形式、≤1 俚语、≤1 文化；任一无法给出 `anchor` 就丢弃）。

### 3.4 深度四档：真正的分级是“讲多深”，不是“讲不讲”

| `teach_depth` | 触发 | 表现 | 占课时 |
|---|---|---|---|
| `mention` | band 差 ≥2，或复现 1 次、非阻断 | 字幕里一条注释（≤20 字），不进 S3 | 0 |
| `explain` | band 差 = 1 | S3 一张卡（**≤35 秒读完**；12 分钟课只放得下 5 张卡，v0.1 的“60–90 秒/卡”会把 S3 撑到 7 分钟） | 有 |
| `practice` | band 差 = 0 且是形式点/产出词 | 卡 + S4 至少 1 题 | 有 |
| `produce` | 固定 2 个词（高频、可迁移、学员能马上用） | 卡 + S5 产出必用 | 有 |

**“不讲什么”的硬规则**（写进 prompt 系统约束）：已掌握（跨 ≥2 日独立提取正确 ≥2 次）不讲；低于 i−2 档不讲；专名/品牌/缩写不讲；只出现 1 次且不影响理解不讲；需要超出形式库才能讲清不讲；文化点无来源不讲；同课两个点考同一事实/同一词去重。

### 3.5 同一内容的三堂课：A2 用自有文章，Kurzgesagt 只做 B1（强脚手架）/ B2

v0.1 用 Kurzgesagt（B2 内容，1,578 词 / 110 块 / 164.6 wpm 块跨度）给 A2 开 basic 课，教 `bot/fake/traffic/steal`——但同一窗口里还有 `saturating/supercharged/dramatic/pretty quickly` 等大量 A2 未知词。这不是 i+1，是“看双语字幕把内容翻译出来”。v1 改法：

**（a）A2 的课用 269 词自有文章（整篇一课）**

| 维度 | A2（basic）——269 词自有文章 |
|---|---|
| 窗口 | 整篇 269 词 / 6 段 → 课程内 3 个阅读段（每段约 90 词，60 秒/段） |
| 主目标 | 能说出“这段在讲什么”，并用 `because` 给出 1 个原因 |
| 目标词（4） | 由教研从候选池确认（4 个高频具体词/语块）；**本表不复述原文，避免编造引文** |
| 形式点 | 教研从 60–100 条人工库选 1 条（如 `there is/are`、`be going to`）；LLM 只写 `why_here` |
| 覆盖率门槛 | 未知 token ≤3%、未知 lemma ≤8/100 词（自有内容可控，预期一次通过） |
| 题量 | 细节 2 / 因果 1 / 词义 2 / 形式 1 + 离场 2（+1 gist 不计分） |
| 产出 | 3 句 `____ is ____. ____ because ____.`（20–40 词，`because` 框架） |
| 脚手架 | 双语常显 + 可回放 + 4 词全预教 |

**（b）同一段 Kurzgesagt 的 B1（core）与 B2（advanced）两堂课**

素材：`content/library/videos/kurzgesagt-ai-slop.json`（1,578 词 / 110 块 / 575 秒 / 164.6 wpm）。下列引文均来自真实块，窗口按块边界。

| 维度 | B1（core，**强脚手架，需覆盖率 ≤5%**） | B2（advanced） |
|---|---|---|
| 窗口 | 3.5–4.2 分钟 ≈ 576–691 词（按 164.6 wpm 算；块数约 40–48，G0 实算） | 4–4.5 分钟 ≈ 658–741 词（块数约 46–52，G0 实算） |
| 主目标 | 能说出“这段在警告什么”，并用自己的话复述 1 个理由 | 能解释“为什么作者说 AI 可能不可逆地破坏互联网” |
| 目标词（4） | `bot`（机器人账号）、`fake`（假的）、`traffic`（流量）、`spot`（识别） | `saturate`（充斥）、`supercharge`（加速）、`spot`（识别）、`irreversible`（不可逆） |
| 形式点 | `things are becoming dramatic`（becoming + adj，表示变化） | `has been sold out to the AI companies`（现在完成被动） |
| 文化/语用 | 0（core 不塞文化） | 1 条语用点：`slop` 的贬义与“AI 生成垃圾内容”的语境（来自 150 条词表） |
| 题量（6+2） | 细节 2（什么是 slop？多少流量是 bot？）+ 词义 2 + 形式 1 + 推断 1 | 细节 1 + 词义 2 + 形式 1 + 推断或语用 2 |
| 离场测（2） | 词义 1（`fake`）+ 形式 1（`is becoming`） | 词义 1（`saturate`）+ 形式 1（`has been sold out`） |
| 产出 | 40–60 词：“用 2 个目标词复述这段在警告什么” | 60–90 词：“Explain why the speaker says AI slop threatens the internet. Use 3 of the target words.” |
| 脚手架 | 英文字幕 + 整句中文可点开 + 4 词全预教 + `saturate` 预教 | 英文字幕；中文只点词；`saturate` 预教、`irreversible` 不预教（挑战） |
| 共享 | 同一条字幕缓存、同一套题目管线、同一套 FSRS；窗口/词/题/产出不同 | 同左 |

**（c）被否决的配置（必须写进 spec，防止回头再加）**：`A2 + Kurzgesagt`。窗口内未知词远超 8 个/100 词，覆盖率闸必然拒绝；要救它只能做 60–90 秒 micro-window + 预教 6–8 词（4 词上限就破了），MVP 不做。

### 3.6 课内自适应：难度是旋钮，不是分数

- S4 首答正确率目标 **65–80%**（basic 可到 80%，advanced 75%）；`<50%` → 下一课降一档、当前课追加 1 个 micro 重讲；`>90%` 且 S2 完成快 → 升一档。
- 给用户一个显式按钮「这节课偏难 / 偏易」；与现有“水平轴”手动覆盖同一套语义。
- `too_hard` 连续 3 次 → 该课进人工复核；这是“讲太多/选太难”的行为报警，而不是用户能力问题。
- **UTR 是估计**：MVP 用 band + `word_states` + `known_lemmas`（从 `review_logs` 派生：≥2 次正确跨 ≥2 日）现算；UI 说“预计难度”，不说“你有 3% 的词不认识”。

### 3.7 A1 与低难度内容的边界（必须诚实）

- **A1 不上真实内容课**：库内所有视频 159–183 wpm；A1 需要 60–120 词/2 分钟，只能走“带读课（Bridge）”或专门录制的慢速内容。
- **Bridge 模式（MVP 只做文案/入口，不做完整生成）**：预教 12 个阻断词 + 3 道细节题 + 建议换更简单内容；不生成讲解/产出。
- **公版文学不是 A2–B1 的救命稻草**：19 世纪英语对 A2–B1 不可理解；公版真正适合 B2/C1 精读。低难度内容只能靠原创（V1 补 2 篇 600–800 词自有文章，¥600–1,600）。
- MVP 的 basic 档以 A2 为下限；A1 用户看到“这节按 A2 起步，建议先做定位测/换一篇短文”，不硬生成。

### 3.8 输入覆盖率闸（v1 新增，第 9 道机械闸）

**问题**：v0.1 有 `band_group`、有 4 个目标词、有双语字幕，但没有“这段到底有几个词他不懂”的硬指标。于是“A2 看 B2 视频”也能生成一课，纸面上叫 i+1，实际是翻译辅助。**i+1 必须是可测量的输入覆盖率，不是口号。**

**三个指标（全部由规则算，0 LLM）**：

| 指标 | 定义 | 用途 |
|---|---|---|
| `unknown_token_rate` | 窗口内 token 中，lemma ∉ (`known_lemmas` ∪ 已 `mastered` 的 `word_states` ∪ 低于 i−2 档高频词) 的比例 | 主门槛：不懂的词占多少 |
| `unique_unknown_lemmas_per_100w` | 每 100 词里的**不同**未知 lemma 数 | 防“同一个难词反复出现”造成假通过 |
| `pre_teach_coverage` | 4 个目标词覆盖的未知 token 比例 | 证明“预教 4 个词”到底救了多少 |

**门槛与动作**：

| 档 | 门槛 | 不达标动作 |
|---|---|---|
| basic | 未知 token ≤3% 且 ≤8 未知 lemma/100 词；视频另需 wpm ≤150 | 换短窗口；仍不达 → 不开 basic 版 |
| core | ≤5% 且 ≤12/100 词 | 换窗口；仍不达 → 降为 basic 试算或不开 |
| advanced | ≤8% 且 ≤18/100 词 | 换窗口；仍不达 → 只做 `mention` 型注释，不出课 |

- 指标写进 `pack.difficulty`（`{word_count, wpm, est_band, unknown_token_rate, unique_unknown_lemmas_per_100w, pre_teach_coverage}`）与 `qc_json`；闸信息可回查，不是一次性计算。
- 公开课/私课都跑；私课不达标时**降级但不阻断**（用户自己的内容，提示“这节对你偏难”），公课不达标**阻止发布**。
- 测试：`test_coverage_gate_rejects_a2_on_b2_video`（Kurzgesagt A2 → 拒绝）、`test_coverage_gate_article_a2_passes`（269 词 A2 文章 → 通过）、`test_coverage_uses_known_lemmas_not_band_only`。
- 代价 2–3 人日（含规则、指标写盘、3 个测试与 1 次金标校准）；收益是“i+1”第一次有了可被证伪的定义。

## 4. 生成管线

### 4.1 总览（内容 → 选段 → 一课 → 学案 → 运行时）

```
content_catalog（text_hash / align_hash / license）
  → passage（video blocks / article paragraphs）
  → profile（规则：wpm、band、候选池、UTR 代理）      [键含 band_group]
  → window（规则：时长 + 词数双约束）                  [键含 band_group]
  → analyze（LLM ①：gist、register、敏感项、上下文定位卡）
  → points + glossary（LLM ②：从候选池选 5 点 × 3 档措辞 + 4 词语境义；form 点只写 why_here）
  → items + output_task（LLM ③：6+2+1 题 + 产出任务 + 范文候选）
  → assemble + 9 道机械闸 → pack（共享或私有）
  → T1 交叉复核（LLM ⑤ 或第二模型：每张讲解卡“能否由引文推出”）
  → plan（规则 + 可选便宜模型：按用户裁剪、scaffold、时间盒）
  → run（作答 / 产出 / 断点 / seen 判定）
  → produce（LLM ④：产出反馈，必须引用学员原文）
```

### 4.2 阶段表：产物、LLM/规则、缓存键、失败语义

| # | 阶段 | 输入 | 中间产物 | LLM？ | 缓存键（v1） | 失败时 |
|---|---|---|---|---|---|---|
| S0 | identity | `content_ref` + 原始块/段 | `content_catalog`：`text_hash`/`align_hash`/license | 否 | `text_hash` | 422（内容不可用） |
| S1 | passage | blocks / paragraphs | 统一 `passage`：`block_index/start_ms/en/zh/lemma/band` | 否 | `(align_hash, pipeline_ver)` | 422（双语覆盖 <95%） |
| S2 | profile | passage + ECDICT | `profile`：wpm、词数、band 估计、候选池 25–40、UTR 代理 | 否 | `(text_hash, band_group, dict_ver)` | 降级“无分级”，仍可出课 |
| S3 | window | profile | `window`：`block_from/to`、`start/end_ms`、候选窗口 2–3 | 否 | `(text_hash, band_group, window_ver)` | 规则兜底“前 3.5 分钟” |
| S4 | analyze | window + passage | `analysis`：gist、register、敏感项、上下文定位卡 | 是（~1.5k in） | `(text_hash, window_key, band_group, target_lang, analyze_ver)` | 省略，直接进 points（质量降级） |
| S5 | points | 候选池 + analysis | `points[5]` × 3 档措辞 + `glossary[4]`；form 点带 `form_id`/`why_here` | 是（2.5k in / 2.1k out） | `(text_hash, window_key, band_group, target_lang, points_ver)` | 取通过的前 N；<3 判失败 |

- **硬上限**：单课输出 ≤**4,200 token（软）/ 5,000（硬）**；单调用 ≤2,400；超过截断/失败，不许“让模型继续写”。
- **为什么从 3,050 上修到 4,200**：5 点 × 3 档（15 段解释）+ 5 个例句/易错点 + 9 题（题干 + 4 选项 + 解析）+ 产出任务 + 范文 + JSON 包裹，实测粗算 4.2–5.3k。v0.1 的 3,050 + 4,000 硬顶会逼着砍点/砍题，和“5 点 + 8 题”的命题直接冲突——**要么承认成本上浮，要么承认课变小**。v1 选前者（成本仍是零头，§9）。
- **每 1,000 输出 token ≈ $0.0025 ≈ ¥0.018**；这是把“$0.006 vs $0.036”争论还原成“每课写多少字”的唯一口径。
- `llm.py` 现在没有 `max_tokens`/`max_output_tokens`，必须加（约 1 人日），否则模型开始“写作文”时成本/延迟不可控；各阶段上限：analyze 700 / points 2,400 / items 2,000 / produce 500 / T1 400。
- **配额与调用次数解耦**：4 次调用 + 1 次复核 = **仍只扣 1 单位/课**（`reserve_quota(job)` 建 job 时扣、失败 `refund`，§5.6）；否则用户 2 节课就没额度（v0.1 只写了规则，没写机制）。

### 4.4 规则 vs LLM：哪些永不交给模型

| 任务 | 用什么 | 为什么 |
|---|---|---|
| 分词 / lemma / 词频带 / 词性 / 音标 / 中文释义 | **ECDICT（补 6 列）+ 规则** | 77 万词条、确定性、0 成本；LLM 给词频带必错 |
| wpm / 句长 / UTR 代理 / band 估计 / **输入覆盖率三指标** | **规则** | 同一输入必须同一输出，才能解释“为什么这课对你是 i+1” |
| 候选词（band > i、TF-IDF、非专名、复现） | **规则** | 把 1,500 词的搜索空间压到 25–40 个 |
| 候选形式点 | **正则模式库 + 人工形式库（60–100 条）** | 可命中、可计数、可用证据校验；**语法解释必须是人工写的** |
| 干扰项候选 | **ECDICT 同 POS 同 band、非同义、长度相近** | 比 LLM 瞎编更可控、更便宜 |
| 段落功能 / gist / 敏感项 | **LLM** | 纯语义，规则做不到 |
| 选点 + 词汇/语用措辞 + L1 对比 | **LLM（只在候选池里选）** | 这是“教学”，也是唯一该花钱的地方 |
| **形式点的“为什么用在这”** | **LLM 只写 `why_here`（≤40 字，必须引用本句）** | 语法解释是最容易讲错的地方，解释正文用人工模板 |
| 俚语/语用识别 + register | **LLM + 人工词表 + 证据闸** | 词典收不全；但必须绑定原文 |
| 文化/百科 | **不做（MVP）**；公课人工写 | 天然不在原文里，无法机械校验 |
| 练习题面/选项/解释 | **LLM + 9 道闸** | 可批量产出，但必须被证据钉住 |
| 讲解卡复核 | **LLM（第二模型，异厂商优先）** | 8 道机械闸只证明“引文真”，不证明“讲得对” |
| 学案编排 | **规则优先**，LLM 只写“为什么这么排” | 编排是组合优化，规则更稳 |
| 判分 / FSRS / 难度校准 / 成本 / 时间轴 / `seen` 判定 | **规则，永不 LLM** | 与计划书 §7.4 一致 |


```
{
  "point_id": "p1",
  "kind": "vocab|form|pragmatic",
  "headword": "...",            // kind=form 时改为 form_id（必须来自给定人工形式库）
  "locator": {"block_index": 4, "quote": "..."},
  "depth": "explain|practice|produce",
  "explain": {"basic": "…", "core": "…", "advanced": "…"},   // ≤60 字/档
  "why_here": "≤40 字，只讲‘为什么用在这句’，必须引用本句片段",

【kind=form 的硬约束】
```

### 4.7 缓存键与矩阵（写进代码常量）

| 产物 | 键（v1） | 作用域 | 失效条件 |
|---|---|---|---|
| passage | `(align_hash, pipeline_ver)` | 部署级 | 切句算法升级 |
| profile | `(text_hash, band_group, dict_ver)` | 部署级 | ECDICT/规则/档位规则变更 |
| window | `(text_hash, band_group, window_ver)` | 部署级 | 窗口规则/档位范围变更 |
| analyze | `(text_hash, window_key, band_group, target_lang, analyze_ver)` | 自有/公版=共享；第三方=private | 该 stage prompt 升级（只重生成该 stage） |
| points | `(text_hash, window_key, band_group, target_lang, points_ver)` | 同上 | 同上 |
| items | `(text_hash, window_key, band_group, target_lang, items_ver)` | 同上 | 同上 |
| pack | `sha256(pack_ver, 各 stage_ver, text_hash, align_hash, window_key, band_group, target_lang)` | 同上 | 任一 stage 失效 |
| plan | `(user_id, pack_id, i_level, template, word_state_hash, plan_ver)` | per-user | i 变化 / 词状态变化 / 模板变化 |
| 负缓存 | 同 pack 键 + `status=failed` + `retry_after` | 同上 | **6 小时**后可重试 |

**缓存键矩阵（实现契约，评审 M3 要求）**：

| 产物 | 含 `band_group` | 含 `align_hash` | 含 `window_key` | 含 `stage_ver` | 备注 |
|---|---|---|---|---|---|
| passage | 否 | **是**（键本身） | — | `pipeline_ver` | 对齐变了就要重切 |
| profile | **是（v1 新增）** | 否 | 否 | `dict_ver` | 候选池按 `i/band` 变 |
| window | **是（v1 新增）** | 否 | 否（选之前算候选） | `window_ver` | basic 2–2.5 分钟 vs advanced 4–4.5 分钟 |
| analyze | 是 | 否 | 是 | `analyze_ver` | 上下文定位卡依赖窗口 |
| points | **是（v1 新增）** | 否 | 是 | `points_ver` | 目标词/候选池按档不同 |
| items | 是 | 否 | 是 | `items_ver` | 题量与难度按档不同 |
| pack | 是 | **是（v1 新增）** | 是 | `pack_ver` | 证据时间点依赖对齐 |
| plan | 否（按用户） | 否 | 是（pack 已含） | `plan_ver` | per-user |

**四条硬规则**：

1. **键不含 model id**，行里记 `generator_model`；模型升级用 `stage_ver` 手动升版 + 金标回归。这个产品 `AI_MODEL_REGION` 切换频繁，键含 model 会让同内容重看命中基本清零。
2. **`text_hash` 不含时间轴**，`align_hash` 含；证据存 `quote + 块范围`，渲染时按当前对齐解析 `start_ms`。现有 `quiz._content_hash` 含 `start_ms/end_ms`，VTT 重解析差 0.3 秒就全量作废——课程不能沿用。测试：`test_pack_cache_survives_vtt_shift_300ms`。
3. **负缓存必须带 TTL**（6h）。现有 quiz 把 rejected 永久缓存，对单阶段是对的；课程一个坏 JSON 不该让用户永远打不开课。
4. **`jobs` 唯一键必须含档位**：现有 `(user_id, kind, content_ref, target_lang)` 不含窗口/档位，两档同时生成会撞同一 job。v1 加可空列 `job_key = sha256(content_ref, window_key, band_group, target_lang)`，并把部分唯一索引 `ux_jobs_active` 改为 `(user_id, kind, job_key) WHERE status IN ('queued','running')`；测试：`test_two_bands_start_two_jobs`。

### 4.8 9 道机械闸与重试（0 人工、每次生成必跑）

| # | 闸 | 检查 | 不通过 |
|---|---|---|---|
| 1 | 结构 | JSON schema；题数/选项数/答案下标；窗口块 id；阶段分钟和 ≤12:30；主动 ≥45% | 整批重试 1 次；仍失败 `failed` |
| 2 | 引文 | `quote` 是 `en_text` 归一化子串（NFC/小写/去标点/压空白）；`start_ms` 落在块内 | 丢弃该条，不整课失败 |
| 3 | 词表 | lemma 在窗口出现 ≥1 次；ECDICT 有词条；band ≤ i+1；非专名/缩写；不在 `known_lemmas`/`word_states` | 丢弃/换词 |
| 4 | 形式 | `form_id` 在人工库（60–100 条）；`pattern` 命中证据句；**`why_here` 含本句 ≥3 词连续子串**；`explain` 与人工模板一致（字符串归一化比对） | 丢弃该点（课降为 4 点） |
| 5 | 对齐 | `objectives ↔ checks` 双向完整；**含“为什么”的目标必须有 `role=causal` 题**；每题有答案与解释；产出任务 ≥2 目标词 + 1 内容名词 | 丢弃/重试 |
| 6 | 语言 | 英文题干/选项无 CJK；中文解释含 CJK；长度上限（题干 160、解释 300、`why_here` 40）；术语 ≤1 | 丢弃 |
| 7 | 安全/许可 | 敏感词表；文化卡来源；公课 `public_display_allowed + derivative_allowed` | 阻止发布/丢弃 |
| 8 | 交叉 | `point_id/item_id` 存在；同课不重复考同一事实；时间顺序正确；`question_id` 可解析到 `questions` | 丢弃/重排 |
| 9 | **覆盖率**（v1 新增） | `unknown_token_rate`/`unique_unknown_lemmas_per_100w`/`pre_teach_coverage` 达档位门槛（§3.8）；视频另查 wpm | 公课阻止发布；私课降级提示 |

**重试策略**：结构失败 → 该 stage 重试 1 次；内容失败 → 逐条丢弃（不整课失败）；`points <3` 或 `items <5` → `partial`，UI 标“精简版”；`form_id` 匹配不到 → 4 点课（不是失败）；仍不合格 → `rejected` + 负缓存 6h，不返回半成品。**绝不用 mock 文字假装成功**。

### 4.9 延迟、异步、预热（“点开即课”物理上不成立）

- **首课 45–120 秒**：4 次调用 + T1 + 重试；p50 60–90 秒、p95 ≤150 秒。8.8k 输出要在 12–18 秒出完需要 489–733 tok/s，没有可用模型能做到。
- **首分钟渐进可用（E1，v1 纳入 MVP）**：S0 目标 + 4 个词 + 播放器 + 上下文卡用规则/缓存先出（目标 **<3 秒**），讲解与题流式补齐。硬指标：**首次交互 <3s、首题可答 <20s、pack 完整 60–120s**；监控三条 p50/p95，超 20% 就告警。这是宪法原则“即时可用，而非完美等待”的具体落点。
- **方案组合拳**：
  1. 播放到 90 秒时后台预生成当前窗口 pack（看完 3.5 分钟，课已就绪）；弃看用户白花 ~$0.016，可接受；
  2. 点“上课”时若未就绪，先给骨架（目标 + 4 个词 + 播放器 + 上下文卡），讲解与题流式补齐；
  3. 还没就绪就回退自由观看 + “这节课稍后可在课程页继续”；
  4. 生成中可离开，完成后通知（复用 `jobs` + SSE）。
- **不要承诺“立即生成”**。封面/入口要有“生成中”态。
- 复看/继续 <1 秒（`course_lessons` 缓存命中）；**换档 20–40 秒**（窗口/points/items 重算）；单题作答 <300ms（本地判分）。

### 4.10 安全与隐私（最小集）

- 学生数据不进 prompt；课 payload 不含 PII；产出文本只在提交反馈时发送，且 prompt 只含文本。
- 不做人脸/声音特征提取；MVP 不录音；V1 录音只本地。
- 输出反馈强制引用学员原文子串（不能引用 = 空话，直接丢）。
- 每张讲解卡带“讲错了”一键上报（E3）：`POST /api/course/{id}/report {reason:"wrong_explanation", pointId}`；周度 30 分钟质量会看 10 条私课 + 5 条公课，按错误类型改 prompt/词表。
- 日志保留 180 天；删除权见 §5.6。
- 提示注入：字幕包 `<TRANSCRIPT>`；无工具；8k 输入上限；标题只在文化卡（V1）出现。

#### 5.2.3 数据生命周期与单一真源（v1 新增，评审 M4）

v0.1 的问题：`payload_json` 存 items，同时又要写 `questions` 表——**两个 source of truth**。v1 定死职责：

| 对象 | 唯一真源 | 缓存/派生 |
|---|---|---|
| 题目正文/选项/答案/解释 | **`questions`** | `course_lessons.payload_json` 只存 `question_id` 列表与展示顺序 |
| 作答流水 | **`attempts`** | `course_runs.exit_correct/exit_total` 是汇总 |
| 学员产出与反馈 | **`course_outputs`**（`revision` 0/1） | pack 里的范文是模板，不是学员产出 |
| 断点位置 | **`course_runs.stage/last_position_ms`** | 客户端 localStorage 只作离线兜底 |
| “窗口已见”证据 | **`watch_events`** | `course_runs.seen_ms/seen_pct` 是归并结果（§6.5） |

**五条硬规则**：

1. **发布即写库**：pack 从 `draft` → `ready` 时，把 9 题写入 `questions`，`id = "{course_id}:{item_id}"`（确定性）；`payload_json.questions` 只存这些 id。
2. **重生成不覆盖作答**：重新生成 → 新 `course_id` + 新 question id，旧题 `status='rejected'`，旧 `attempts` 保留可读。测试：`test_regenerate_keeps_old_attempts_readable`。
3. **重写留两稿**：`course_outputs.revision` 0/1 + `UNIQUE(run_id, revision)`；`feedback_json` 按 revision 各存一份。测试：`test_rewrite_keeps_first_draft_and_feedback`。
4. **重上留两次**：`course_runs.attempt_no` + `UNIQUE(user_id, lesson_id, attempt_no)`；`completed` 行不可变。测试：`test_retake_does_not_overwrite_first_attempt`。
5. **溯源不丢课**：`word_sources` 去重键从 `(word_state_id, content_ref, sentence_id)` 改为 **含 `course_id`**；命中已存在同一句时**更新 `course_id`**（而不是跳过）。测试：`test_word_source_records_course_id_when_sentence_exists`。

**删除级联（必须测）**：注销/删除内容 → 删 `course_outputs` → `course_runs` → 该 `owner_id` 的 `course_lessons` → 这些课下的 `questions`（`course_id LIKE 'cl_%'`）与 `attempts`；`content_catalog` 私有行删行或把 `source_ref` 哈希化；公课不受影响。测试：`test_delete_user_cascades_course_data`、`test_private_catalog_source_ref_removed_on_delete`。

### 5.4 API 契约（`/api/course/*`）

| 方法 | 路径 | 鉴权 | 请求 | 响应 | 错误 |
|---|---|---|---|---|---|
| POST | `/api/course/start` | 登录（私课）/ 游客（公课） | `{kind, contentRef, targetLang?, template?, windowKey?, bandGroup?}` | 200 `{courseId,status:"ready",plan,...}` / 202 `{courseId,status:"generating",jobId,skeleton,...}` | 400/403/404/422/429/503 |
| GET | `/api/course/{id}` | 同上 | — | `{course,plan,points,glossary,questions(不含答案),goal,difficulty}` | 404（越权不泄露）/503 |
| GET | `/api/course/{id}/status` | 同上 | — | `{status,jobId,progress,partial}` | 404/503 |
| POST | `/api/course/{id}/progress` | 同上 | `{stage,segment,positionMs,clientEventId}` | `{ok:true,seenPct}` | 400/404 |
| POST | `/api/course/{id}/answer` | 同上 | `{questionId,chosenIndex,elapsedMs,clientEventId}` | `{correct,answerIndex,explanation,evidence:{locator,startMs?}}` | 400/404/409 |
| POST | `/api/course/{id}/output` | 同上 | `{text,selfCheck:[...],revision:0}` | `{wordCount,targetWordsUsed,rubric,modelAnswer,feedback?}` | 400/404/422 |
| POST | `/api/course/{id}/rewrite` | 同上 | `{text,revision:1,clientEventId}` | 同上（写新 revision 行，不覆盖初稿） | 400/404/409（已有 revision 1） |
| POST | `/api/course/{id}/complete` | 同上 | `{exitAnswers:[...]}` | `{hardComplete,softComplete,exit:{correct,total},wordsEnqueued:[...],nextLesson?,receipt}` | 400/404/409 |
| POST | `/api/course/{id}/report` | 同上 | `{reason, pointId?, questionId?}`（`wrong_explanation`/`unsafe`/`broken`/`too_hard`） | `{ok:true}`（事件 + 队列） | 400/404 |

**语义**：

- `start` 幂等：同一 `(owner_id, content_ref, window_key, band_group, target_lang, prompt_version)` 返回同一 `courseId`；不重复扣配额。
- 生成走 `jobs`（`kind=course_pack`），`job_key` 含窗口/档位（§4.7），两档并发不串 job；`GET /status` 或 `GET /api/jobs/{id}` 轮询；SSE 可选。
- `answer` 复用 `quiz.answer_question` 判分语义；`attempts` 表照写；`course_id/role/window_key/locator_json` 进 `questions`；`role=gist` 的题判分但**不计入** `exit/主体完成` 的门槛。
- `complete` 调后端 `is_course_complete(run_id)`：`soft` = UI 可显示的“上完了”；`hard` = `window_seen()` ∧ ≥5 题作答 ∧ 产出已提交（§6.5）。**`course_complete` 事件只在 hard 达标时发**。
- 旧 `/api/lesson/*` 保留（理解题）；课程不再调用旧接口，直接走 `/api/course/*`。
- 文章课的 `evidence` 返回 `{locator:{kind:"article",paragraphIndex,sentenceIndex,quote}}`，**没有 `startMs`**；前端滚到段/句，不 seek。
- 游客：公课（3 篇自有文章）可上，进度存 localStorage，登录后幂等认领；私课（视频/第三方）必须登录。

## 6. 前端课程空间

### 6.1 信息架构：不是第 5 个 tab，也不是一个开关

| 方案 | 判定 | 理由 |
|---|---|---|
| A 独立“课程”tab | **否** | 底栏 4 项是拇指区上限（IA 文档已冻结）；“课”是动作，不是目的地方向 |
| B 学习页加“课程模式”开关 | **半否** | 开关是“设置感”；无法深链、无法进“继续学习”卡、无法进今日计划 |
| C 子路由 `#/course/<id>` + 共享组件 | **采用** | 课有生命周期（开始/中断/完成）、需要稳定 ID 被深链；内部复用播放器/字幕 |

**共存答案：两态一个内容、可逆升级/降级。**

```
#/learn/youtube/<videoId>   ← 浏览态（现状，1 击可达，老用户不被剥夺）
        ⇅  「把这集变成一堂课」/「随便看看」
#/course/<courseId>         ← 课程态（有目标、有分段、有产出）
```

- 浏览态点“上课”→ 进课程态，**从当前秒开始切段**（不是回到 0:00）。
- 课程态点“随便看看”→ 退回浏览态，**播放位置与作答全部保留**。
- 游客可上 3 堂公课（自有文章）；视频私课必须登录。

### 6.4 段末交互（v1 重写，与 §2.2 对齐）

v0.1 的 §6.4 是“每段暂停 → 讲解 → 1 题 → 继续”，与 §2.2 的“连续看 4 分钟 → 集中讲解 → 6 题”冲突，且按它算会变成 14–18 分钟、总题量只有 2–3 道。v1 统一为**分段交错**，逐帧写清：

```
段 N（N=1..3）播放到该段最后一句 end（不中途停）
  → player.pause()（自动）
  → 讲解态：该段 1–2 张卡（每卡 ≤35 秒读完）
       · 卡片可点回原句（视频 seek / 文章滚到句）
       · 右上 [检查一下 →]（强用户可跳过讲解直接做题）
  → 点 [检查一下] → 练习态，依次出 2 题（mcq/tf）
       · 提交即判分；答错不重做
       · 反馈 1 行 + [回那一句 mm:ss]（sheet 收回 44）→ [继续第 N+1 段]
  → 段 3 做完（6 题齐）→ S5：产出（90 秒）→ 范文/自评 → 2 道离场测 → 收据
```

- **先讲解后出题**：出题在前 = 考没教的东西（挫败）；讲解在前 = “我刚讲完，来验一下”（自然）。
- **总题量 = 3 段 × 2 = 6 主测 + 2 离场**，**删掉 v0.1 的“总题量 = 段数 + 1”公式**（它和 6+2 自相矛盾）。
- **不做**：同题重做、计时、红叉/音效、段中途弹题（深度课例外且必须暂停）。
- 文章课把“播放到 end”换成“滚到该段末 + 点[读完这段]”，其余一致。

### 6.5 进度、续学、完成

| 间隔 | 呈现 | 理由 |
|---|---|---|
| <30 秒（切后台） | 什么都不弹，原地续 | 弹“继续上次”是最烦的打断 |
| 同会话/次日 | 卡片「接着上次：第 2 段 · 01:41 · [继续] [重看这段]」 | 段号比百分比有信息量 |
| >14 天 | 「这堂课放了 2 周 · [从第 1 段快速过一遍（3 分钟）] [从第 2 段开始]」 | 直接跳第 2 段是错的：讲解点/词已遗忘；先给“快速过”（S1 预览 + 4 词） |

- 播放位置 **5 秒节流**；段完成与作答立即写（幂等 `clientEventId`）。
- **“窗口已见”的定义（评审 M5，必须写进 spec）**：`window_seen(run_id)` =
  `seen_ms ≥ 0.8 × (window_end_ms − window_start_ms)`，其中 `seen_ms` 只累计**有播放前进**的毫秒（`watch_events.watched_seconds` 归并，复用 `reports.record_watch_events` 的幂等键）；**替代口径**（文章或无 watch 数据时）：≥70% 的段有 `block_visible` 且 dwell ≥1s。
  据此有两条测试：`test_seek_to_end_is_not_seen`、`test_background_play_is_not_seen`。
- **完成判定后端函数** `is_course_complete(run_id)`：
  - **soft**（UI 显示“上完了”）：到达 S5 且产出已提交（允许窗口没看满，给“再看一遍”提示）；
  - **hard**（配额、完课率、效果统计只用它）：`window_seen()` ∧ ≥5 题作答（不含 gist） ∧ 产出已提交。
  前端只读这两个布尔；**只看完不算完成，拖到片尾也不算**。
- 进度点阵 `● ● ○`（3 段；已完成=蓝实心 / 当前=蓝描边 / 未到=`zinc-700`）；**不做百分比**（百分比说的是加载）。
- 成就只做证据触发（第一次不看字幕看完 3 段 / 第一次交出 1 句复述 / 累计 100 词进复习），不做打卡/XP/排行榜。
- **次日 / 第 7 天 60 秒回访卡（E2）**：首页一张卡，点开 = 4 个到期词 + 上节课 1 个形式点，60 秒内做完（次日回收、第 7 天做保持检验）；复用 `routes_review`，不新增表；点击记 `course_open{entry:"review_card"}`。
- **课后“收据”（E4）**：完成后显示“4 词 + 1 形式 + 8 题 + 1 段产出 + 下次复习日”，可分享但只显示统计与 1 句，不导出整课；复用 `LessonRecap`，不新增数据。

### 6.6 与视频页/阅读器的关系

| | 视频课 | 阅读课 |
|---|---|---|
| 段单位 | 时间界（70 秒 / ~15 块，共 3 段） | 段界（2 个自然段合并 ≈90–110 词，共 3 段） |
| 独有讲解组 | 发音/连读、语域、语调（V1） | 句法拆解（主干→修饰→指代）、逻辑连接、文体 |
| 素材 | `VideoPlayer` + `TranscriptView` | `ArticleBody`（从 `ReaderScreen` 抽） |
| 证据 | `locator{start_ms}` → seek | `locator{paragraph_index,sentence_index}` → 滚到该段/句 |
| 入口 | 视频学习页“把这集变成一堂课” | 阅读器“开始精读课” |

- 共享 `LessonShell`、`ExplainList`、`QuestionCard`、`OutputComposer`、`LessonRecap`、`SegmentedRunner`；组定义由后端 `modality` 字段给。
- 阅读器现有“显示/隐藏译文”开关直接复用；视频现有字幕工具栏直接复用。
- **不复制播放器**；`VideoPlayer` 的 `key` 在整个课程态内稳定。

### 6.7 前端验收（A1–A15，关闸全绿）

| # | 验收 | 判定 |
|---|---|---|
| A1 | 375px 下视频全显可见 ≥4 句、折叠 ≥6 句；无横向滚动；sheet 不遮挡高亮句 | 375×812 截图逐屏数 |

### 7.2 发布闸（系统层硬校验，不靠自觉）

```
公课发布前（全部为真才可发布）：
  course_lessons.owner_id IS NULL
  AND content_catalog.public_display_allowed = 1
  AND content_catalog.derivative_allowed = 1
  AND content_catalog.license_type IN ('owned','public_domain','licensed','permission')
  AND content_catalog.checked_by IS NOT NULL
  AND content_catalog.license_evidence_url IS NOT NULL      -- v1 新增
  AND course_lessons.status IN ('ready','partial')
  AND qc_json.coverage.passed = 1                            -- v1 新增（§3.8）
否则：阻止发布（API 422 / 后台按钮置灰）
```

- **没有台账的源，不进公课**；私课可以没有正式许可，但必须 `license_type='private_only'` 且 `owner_id=user`。
- `content_catalog` 1.5 人日、向后兼容；**现在必须做**，否则“公课”在系统层不可实现（`content_items` 连 license 列都没有）。
- 分享卡只显示标题 + 译文 1 句 + 统计；**不导出整课、不导出整段字幕、不做 SEO 公开页**。
- 公课“AI 生成，已人工审核”；私课“AI 生成，未经人工审核”；不得写“老师亲授”。

### 7.3 敏感内容（私课路径的最大政策风险）

| 命中 | 行为 |
|---|---|
| 明确暴力/色情/涉恐/涉未成年/赌博/医疗与投资建议 | **不生成课**；只保留翻译/查词；一句话提示“这段内容暂不适合做成课程”，不解释理由 |
| 政治敏感/宗教争议/身材羞辱/成功学 | **只生成词汇 + 理解题**；不生成讲解、文化注解、产出题 |
| 争议但可处理 | 生成课；讲解只做语言层；文化卡 0；人工抽检 100% 前 20 节 |
| 用户内容含他人音乐/画面/肖像 | 私课可嵌入；不做公课；不做人脸/声音特征提取 |

- 分类器 + 词表 + 人工抽检 2%；误杀率用举报反馈校准（0.3 + 1 + 0.5 人日）。
- **不拒绝用户看这条视频**（他已经在看），只是不给它做课。
- 未成年人：首发 18+ + 年龄门（计划书已决）；用户 vlog 里的孩子：不做公课、不做人脸识别、不录音。
- 隐私：学生数据不进 prompt；课 payload 不含 PII；运营日志 180 天。

### 7.4 文化点/背景：MVP 的诚实形态

- **背景** = 上下文定位卡：1 句原文（前/后 2 个窗口）+ ≤20 字改述；不含外部知识；可机械校验（quote 必须是原文子串）。
- **文化** = 公课 1 条人工策展 `language_culture` 卡（≤60 字），标注“补充，非原文”，不进考题；私课 0 条。
- **词源永久禁**；百科/历史/宗教/政治断言 MVP 0；V1 做也必须 URL + 人审 + fail-closed（无来源不展示）。
- 为什么这么保守：每课 1 条 AI 文化点 = +8 分钟人审；200 课/周从 6.7 小时变 33 小时（5 倍人力），而它不进考题、不影响“能不能用英语做一件事”。

### 7.5 下架与合规

- 涉违法 **4 小时**内下线；版权投诉 **24 小时**内首次答复；误下架 **72 小时**内复核。
- 每季度一次下架演练；审计日志；涉及用户数据时通知。
- 公课来源变更/许可到期 → 该来源全部课暂停，重新核许可。
- 年度版权/隐私复核；`content_catalog` 台账是唯一真源。

## 8. 质量体系

### 8.1 四层质量（AI 不能批准上线）

| 层 | 谁 | 判什么 | 覆盖 | 成本 |
|---|---|---|---|---|
| **T0 机械闸** | 代码 | 结构/引文/词表/形式/对齐/语言/安全/交叉/**覆盖率**（§4.8） | 100% | 0 |
| **T1 模型交叉复核** | 第二模型（异厂商优先） | 每张讲解卡能否由引文 + 词表推出；有无事实/语法错；fail-closed | **100%（MVP 起，公课 + 私课都跑）** | +$0.0011/课（约 7%） |
| **T2 人审** | 教研/审校 | 10 项 rubric；公课签字；私课抽检/举报 | 公课 100%（MVP）；私课 0% + 2% | ¥80/h |
| **T3 金标** | 教研双人 | 20 case 盲评；κ≥0.6 | 每次 prompt/模型/大纲变更 | 4 人日建 + $0.24/次回归 |

> 沿用计划书 §9.4 的教训：**“引文存在”与“答案可证”必须是两个指标**。前者是 100% 机械断言，后者是 ≥90% 的可观测质量率；混在一起会让人误以为“引用真句”就等于“题对了”。
>
> **v0.1 的问题是公私双标**：公课 100% 人审，私课 0% 人审 + 2% 抽检 + T1 写在 V1。但私课才是视频主路径，也是用户最可能撞见语法错误的地方。v1 把 T1 提到 MVP 并覆盖所有讲解卡——它不是“更好”，它是“私课质量的唯一闸”。

### 8.2 Rubric

**教学点（每条 0–2）**：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| **准确性**（一票否决：错即 rejected） | 释义/用法错 | 基本对但不够准 | 准确且贴合本句语境 |
| **锚定** | 通用词条复述，和这句无关 | 引了原句但没讲清 | 明确讲“在这句里它是什么意思、为什么” |
| **级别匹配** | 用了更难的词解释 | 能懂但要查词 | 用学员级别内的语言，术语有解释 |
| **克制** | 塞词源/百科/考试技巧 | 略多 | 只讲必要信息，≤60 字讲完 |

**形式点单列**：`explain` 来自人工模板（与 `content/grammar/forms.json` 逐字一致，归一化比对），人审只判 **`why_here` 是否准确 + 是否真的引用了本句**（0/1/2）。LLM 写的语法解释一律进 `rejected`——这是 v1 的硬边界。

**题目（每条 0–2）**：答案唯一且能由引文推出；干扰项“似是而非”（同词性/同话题/长度差 ≤1.5×）；解析写“为什么错项错”。**产出**：任务完成 / 目标语言使用 / 可读性，各 0–2，不展示总分。

**一票否决**：词源断言、无来源百科、宗教/政治断言、“这个词在英语里就是……”式绝对化（未标注语域）、用另一个生词解释生词、把网络热词教成“常用表达”、对文化现象做因果断言、**LLM 自写的语法规则**。

### 8.3 金标集

| 项 | MVP | V1 |
|---|---|---|
| 规模 | **20 case** | 90 case |
| 构成 | 6 文章（3 篇 × 2 档，含 A2 整篇）+ 10 视频（3 免费库 + 7 用户脱敏）+ 4 边界（A2 极简 / C1 复杂 / 敏感 / 无字幕） | 视频 50% / 文章 35% / 剧集 15%；A2/B1/B2/C1 各 25% |
| 每条标 | 3–6 个“值得教”的点 + 理由；2 个“不值得教”陷阱；1 道参考题；**1 组覆盖率数字** | 同左 + 反例 |
| 成本 | 45 分钟/条/人 × 2 人 × 20 = 30 小时 = **4 人日** | 24 人日 |
| 信度 | 抽 30% 双人独立标注，**κ≥0.6** 才可用；<0.6 先改规范 | κ≥0.7 才独立签字 |
| 回归 | 每次 prompt/模型/大纲变更跑；20 × $0.0162 = **$0.32/次** | 90 × $0.04 = $3.6/次 |

> 用户内容进金标前必须脱敏并取得同意；**只存标注（点/答案/理由/覆盖率），不存正文**。

**指标门槛**：教学点召回 ≥80%（词）/≥70%（语法）/≥75%（俚语）；精确率 ≥85%；分级相邻一致率 ≥85%（完全一致 ≥60%）；引文存在率 **100%**；答案可证率 ≥90%（MVP）/≥95%（V1）；讲解事实错误 ≤2/100（MVP）→ ≤1/100（上线门槛）；干扰项合格率 ≥75%；**覆盖率闸误判率 ≤5%（抽样人工复核 20 例）**。

### 8.4 人审：主成本，按版本/抽样，不按课全检

| 场景 | 量 | 标准 | 成本 |
|---|---|---|---|
| 首发公课（MVP） | **9 个 pack 预生成，按难度矩阵开放 5 个有效 + 1 个实验**（§10.4） | 引文 100%、形式 100%、文化事实 100%、题可答 100%、覆盖率达标 | 主档 3 × 35 分钟 + 变体 2 × 12 分钟 ≈ **2.3 小时**（一次性） |
| 每个 prompt 版本 | 20 case 盲评 | 机械闸不替代人：语法/文化/题感 | 4 人日/版本 |
| 私课 | 0% 人工 + **T1 100%** + **2% 抽检**（MVP）/0.2%（稳态）+ 100% 举报 | 10 分钟/条 | 8,000 课/月 × 2% = 160 条 × 10 分钟 ≈ **27 小时/月**（MVP）；0.2% ≈ 2.7 小时/月 |
| 形式库建设 | **60–100 条**（每条：CEFR + regex + 2 个人工例句 + explain_template） | 命中率 ≥70%、无误标 | **3–4 人日**（v0.1 写 2 人日做 20–30 条，太小且太便宜） |
| 产出范文 | 10 篇/版本 | 与任务对齐、目标词自然 | 0.5 人日 |

- **时薪口径 ¥80/h**（中国兼职教研市场价），与 TO 一致；全量细审 30–35 分钟/12 分钟课，例外审核 12–18 分钟，抽检 2 分钟——**三种口径对应三种东西，报价必须写清**。
- **招聘**：英语专业硕士/前机构老师/英语博主；C1+ 英语、中文母语、能按 rubric 写具体修改意见；90 分钟测试 + 5 节付费试审；校准 **κ≥0.7** 才独立审稿；**招聘 lead time 4–8 周，W1 启动**；前 2–3 周用外包（¥80/h，预算 2–3 人日）顶形式库与 pack 审校。
- **0.5 FTE 教研主编**（¥12k–18k/月）是下限；没有它，讲解错误率会从 1/100 漂到 5/100，而你不会知道。
- **周度 30 分钟质量会（E3）**：抽 10 条私课 + 5 条公课，按错误类型（事实/过度解读/文化偏见/语法解释错/题不可答/目标词超纲）记录并改 prompt/词表；0.1 FTE 就能跑。
- **AI 不能批准上线**；审校不能批自己写的课；运营只发布不改内容；法务只批许可不批教学。

### 8.6 评测效度：先定指标，再看数据；n<100 一律“初步”

| 层 | 指标 | 门槛（Go） | 说明 |
|---|---|---|---|
| 过程 | 主体完成（`window_seen` ∧ ≥5 题） | ≥65% | 低于 40% 先怀疑课太长/太重 |
| 过程 | 课程完成（hard complete） | ≥35%（MVP）/≥45%（V1） | **严格完成 ≤ 产出提交率**；两个口径分开报，不要用“完课率”掩盖“产出率” |
| 过程 | 产出提交率（到达 S5 的人里） | ≥55% | 输出是“学没学”的最强行为信号 |
| 即时 | 离场测正确率 | 65–85% | 太高=太简单/在教考试；太低=i+5 |
| 延迟 | 7 天目标词保持率（FSRS good/easy） | ≥70%，且不低于“用户自加词”基线 | FSRS 目标 0.9，新词 7 天 70–80% 是常态 |
| 迁移 | 10 个**未教过**句子里目标词填空 | ≥70% | 测“会用”而不是“记得这课” |
| **迁移（主终点 ①）** | **7 天后新的 3–5 句 can-do 任务**（同 rubric，2 名评分员盲评，κ≥0.6） | 效应量 d ≥0.4 | 课的 claim 是“能用英语做一件事”，不是“记住 10 个词” |
| 行为 | 7 天内再上一课 | ≥35% | 课程化的留存判据 |
| 护栏 | 自由观看分钟数 | 降幅 ≤5pp | 课不能把“看内容”挤掉 |
| 护栏 | 理解题完成率/正确率 | 不降 | 课不能拖累主线 |

**效度纪律**：

- 离场测测的是“本课教过的”，天然高估；**延迟测 + 迁移测才算学会**。
- **双主终点**：① 任务级 can-do 迁移（3–5 句新 prompt、双评分员、κ≥0.6）；② 7 天目标词保持/迁移。**预注册主终点、分析计划、MDE**；`n≈30` 只作 pilot，不宣称“有效”。
- 小样本（n<30/组）不做显著性宣称，报效应量与置信区间；n<100 用户标“初步”。
- Go/No-Go 用**过程指标**（主体完成 ≥65%、产出提交 ≥55%、7 天再上一课 ≥35%）闸门；学习信号单独报，不混进 go/no-go。
- 不做“保证学会/提分/达 B2/相当于雅思 X”表述；课是“有结构的练习”，不是课程认证。
- 保留 1 个反例指标：**“课上看懂、7 天后忘光”的比例**——这是这套设计最可能的失败模式。

## 9. 成本与单位经济

### 9.1 统一成本公式（先消灭“$0.006 vs $0.036”的假争论）

```
成本/课 = in_tok × $0.30/M + out_tok × $2.50/M      # 账本口径（当前唯一有价目）
真实口径 = 上式 × 0.4–0.5                            # DeepSeek/Qwen 实价填入 MODEL_CATALOG 后重算
每 1,000 输出 token ≈ $0.0025 ≈ ¥0.018 ≈ 一次视频翻译的 1/3
```

五份分册的单价其实一致（in $0.30/M、out $2.50/M），差异 **100% 来自每课写多少字**：2.1k → 8.8k 输出，对应 $0.006 → $0.029。**控制成本的唯一杠杆是“每课讲几个点、出几道题”，不是换模型。**

### 9.2 单课 token 账（v1）

| 项 | in tok | out tok | 账本成本 | 备注 |
|---|---|---|---|---|
| analyze | 1,500 | 450 | $0.00158 | 只给字幕块 |
| points + glossary | 2,500 | 2,100 | $0.00600 | 5 点 × 3 档 + 4 词语境义；form 只写 why_here |
| items + output | 1,800 | 1,650 | $0.00467 | 6+2+1 题 + 产出任务 + 范文 |
| **生成小计** | **5,800** | **4,200** | **$0.01224** | out/in = 72.4% |
| 15% 重试 | — | — | $0.00184 | 设计上限 ≤$0.0145 |
| produce（提交后） | 900 | 300 | $0.00102 | 3 项 rubric |
| **T1 复核（v1 新增）** | 1,200 | 300 | $0.00111 | 全量讲解卡 |
| **单课合计** | **7,900** | **4,800** | **$0.01621** | ≈ ¥0.115 |
| **真实口径** | | | **≈$0.0065–0.0081** | ≈ ¥0.046–0.057 |

- **硬上限 4,200（软）/ 5,000（硬）输出 token**；超过就砍题/砍讲解，不是“让模型省着写”。
- **讲解 ≤1,700 输出 token（40%）**：这是硬预算，不是建议；否则题与产出会被挤掉。
- **与 v0.1 的差异**：3,050 → 4,200（+37.7%），单课 $0.0118 → $0.0162（+37%）。原因是 5 点 × 3 档 + 8 题 + 范文在 JSON 里的真实体积；评审的粗算 4.2–5.3k 与本计划的 4.2k 一致。
- **$0.0162 是账本上限，不是终值**：`MODEL_CATALOG` 里 DeepSeek/Qwen 全是 `None`，账本按 Gemini 最贵记，**高估约 1.7×**；填价前所有预算/毛利判断都要按“真实口径 0.4–0.5×”读。

### 9.3 月度场景

| 场景 | 量 | 账本成本 | 真实成本 | 备注 |
|---|---|---|---|---|
| 1,000 MAU × 8 课/月（私课，不共享） | 8,000 课 | **$130/月** | **≈$52–65/月** | 每课 $0.0162 |
| 1,000 付费 × 30 课/月 | 30,000 课 | **$486/月** | **≈$194–243/月** | 每课 $0.0162；≈¥3,451（账本）/ ¥1,380–1,730（真实） |
| 3 篇公课 × 3 档预生成 | 9 课 | **$0.15 一次性** | $0.07 | 自有内容可共享，延迟 0 |
| 公课 8 节/月人审 | 8 × 30–35 分钟 | — | **¥960/月** | ¥120/节全成本 |
| 私课 0.2% 抽检（8,000 课） | 16 课 × 10 分钟 | — | **¥213/月** | 稳态 |
| 私课 2% 抽检（MVP） | 160 课 × 10 分钟 | — | **¥2,133/月** | 仅 pilot 期 |

**结论**：1,000 付费场景下 AI 成本约为月收入的 **5–12%**（账本 11.9%、真实 5.4%），仍是零头；**人审/内容供给才是主成本**（公课 ¥120/节）。不要为了省 $0.005/课砍掉产出或减少题量——那会把差异化砍没。

### 9.4 人审成本（真正的主成本）

| 项 | 分钟/课 | 成本 | 说明 |
|---|---|---|---|
| 公课一审（12 分钟课） | 30–35 | ¥40–47 | 10 项 rubric + 逐题核对 + 覆盖率数字抽查 |
| 公课选题/许可/编辑/发布 | 50–60 | ¥67–80 | 与审校并行 |
| **公课全成本** | **90** | **¥120** | 成熟模板后可降到 ¥80 |
| 私课边际 | 0 | ¥0.12–0.23（AI + T1 + 机器闸） | 不含人审 |
| 私课 QA 摊销 | 0.2% × 10 分钟 | ¥0.03–0.1/课 | 举报另算 |
| 举报复核 | 10 | — | 24h 内首次答复 |

- **倍数口径（v1 重算）**：AI 单课 ¥0.115；单笔人审 ¥40–47 → **约 350–410 倍**；公课全流程 ¥120 → **约 1,000 倍**。v0.1 的“500–1,400 倍”是按 $0.0118 算的，随 token 上修而下降，但量级结论不变。
- 1 FTE 审校 = 30 小时/周 ÷ 35 分钟 ≈ **50 节/周**（纯审）；含会议/行政 **35–40 节/周** ≈ **150 节/月**。
- 0.2 FTE（8 小时/周）≈ **12–14 节/周**（纯审）≈ **50–60 节/月**；全流程公课按 90 分钟/节 ≈ **20–25 节/月**。
- **公课产量规则：每月新增公课 ≈ 付费用户数 ÷ 25**（按 ¥120/节、60% 毛利线）。50 用户 2 节/月、100 用户 4 节/月、200 用户 8 节/月、500 用户 20 节/月、1,000 用户 40 节/月。
- **年付警告**：$49/年 ≈ ¥29/月，计入课程成本（30 课 × ¥0.115 ≈ ¥3.45 + 抽检/支持）后毛利约 45–52%，达不到 60%；**建议 $59/年或年付不含人工加购**。

### 9.5 免费/付费分层

| 档 | 公课 | 私课 | 人工精读 | 复习/周报 |
|---|---|---|---|---|
| 免费 | 3 节/月（轮换） | 3 节/月 | 无 | 无限 |
| 付费 $6.99/月（¥29 等值） | 全量（8–12 新/月 + 存档） | 30 节/月 fair use | 无（加购） | 无限 + 导出 |
| 加购 | — | 30 节 ¥19 | ¥49/节；5 节 ¥199 | — |

- **原则**：成本≈0 的功能慷慨，成本>0 的功能计量，**人时永远不包月**。
- 免费用户成本：3 私课 × ¥0.115 + 公课摊销 ¥0.12 + 支持 ¥0.5 ≈ **¥1.0–1.3/月**；1,000 免费用户 ≈ ¥1,000–1,300/月；需要 ≥10% 转化，或把免费私课降到 1 节/月。
- 私课日限额：免费 1 节/日（月 3）、付费 3 节/日（月 30）；同一内容重生成 1 次免费，之后排队/计费。
- 人工精读 ¥49/节**只按次卖**，绝不放进 $6.99 包月（¥40–60 成本 vs ¥49 月费，数学上不可能）。

### 9.6 缓存与批处理

- **共享口径**：自有/公版 = shared（`owner_id=NULL`）；第三方/用户自带 = private（`owner_id=user`），不跨用户缓存。这是合规成本，不是设计缺陷。
- **预热**：① 自有内容（3 篇文章 × 3 档 = 9 个 pack）提前生成，成本 ≈$0.15；② 用户播放到 90 秒时后台生成当前段 pack；③ 不做第三方目录预生成。
- **不做 provider 批处理**：Gemini 批量折扣大陆不可用；国内对话模型没有稳定批量通道；省 50% 换 24h 延迟，对首课不划算。
- **负缓存 6h**；缓存命中率是 KPI（公课目标 ≥80%；私课 0% 跨用户，只做同用户重看命中）。
- **归档**：事件按月归档；pack 90 天冷存；单实例 ≤1,000 MAU；V1 Postgres 触发条件写进运行手册。

### 9.7 四个成本陷阱（必须在上线前修）

1. **账本高估 1.7×**：DeepSeek/Qwen 价目是 `None`，按 Gemini 最贵记；1 行配置不填，所有成本报表、预算闸、毛利判断都是错的。**上线前填 `MODEL_CATALOG`。**
2. **按调用扣配额**：一个 pack 4 次调用 + 1 次 T1，若按调用扣 5 单位，用户 1 节课就没额度；**必须每课 1 单位**，且要有 `reserve_quota`/`refund` 机制（v0.1 只写了规则）。
3. **全局日预算**：`AI_DAILY_BUDGET_GLOBAL_USD=20` 不是给 1,000 MAU 准备的（8,000 课/月 ≈ $4–5/天，叠加翻译会逼近上限）；1,000 付费时需提到 $40–60 或加课程专属预算。429 文案必须区分“课程额度”与“复习/查词不受影响”。
4. **缓存键缺 band**：profile/window/points 键不含 `band_group` 时，**第一个用户选的档会决定所有人的课**——A2 用户先上课，B2 用户就拿到 A2 的窗口和词表。这是 v0.1 埋得最深的坑（§4.7）。

## 12. KPI 与验证实验

### 12.1 指标树（一个北极星 + 三层护栏）

**北极星**：**每周完成 ≥1 节 hard-complete 课的用户数（Course WAU）**；目标 W8 达到 WAU 的 **25%**。

| 层 | 指标 | 目标 | 说明 |
|---|---|---|---|
| 入口 | 课程入口曝光 → 开始 | ≥25% | 入口只在“看完/暂停”后出现；不强制 |
| 漏斗 | 开始 → S1 → 段1 → 段2 → 段3 → S5 | 每步 ≥85%（S2 ≥88%） | 单阶段流失 >25% 就改设计 |
| 完成 | 主体完成（`window_seen` ∧ ≥5 题） | ≥65% | 课太长/太重时先掉这个 |
| 完成 | 课程完成（hard） | ≥35%（MVP）/≥45%（V1） | 严格完成 ≤ 产出提交率 |
| 产出 | 到达 S5 的人里提交产出 | ≥55% | 最强行为信号 |
| 回访 | 7 天内再上一课 | ≥35% | 课程化留存判据 |
| 回访 | 次日回访卡点击率 / 60 秒完成率 | ≥25% / ≥70% | E2 的效果闸 |
| 学习 | 7 天目标词保持率 | ≥70% | FSRS good/easy；对比自加词基线 |
| 学习 | 10 个未教句子目标词填空 | ≥70% | 迁移，不是“记得这课” |
| 学习 | 7 天 can-do 任务（双评 κ≥0.6） | 效应量 d≥0.4 | 主终点 ① |
| 质量 | 引文 100% / 答案可证 ≥90% / T1 ≥97% / 错误 ≤1/100 | 上线门槛 | 任一不达标不上线 |
| 成本 | ≤$0.0162/课；p95 ≤150s；首屏 <3s | 每课 | 账本口径 |
| 护栏 | 自由观看分钟降幅 | ≤5pp | 课不能挤掉“看内容” |
| 护栏 | 周报 3 个数字 | 不变 | 课次只进事实句 |
| 护栏 | 举报率 | <2% | 2 次/30 天重审 |

### 12.2 漏斗埋点（7 个事件足够）

`course_open → course_stage_complete(S0..S5, segment 1..3) → course_word_check → course_answer(role 含 gist) → course_output_submit(revision) → course_complete(hard) → course_too_hard`。每个事件带 `courseId/userId/bandGroup/stage/elapsedMs`；不埋额外 PII。次日回访卡复用 `course_open{entry:"review_card"}`，**不加第 8 个事件**。

### 12.3 验证实验（如何证明“课程比翻译+查词更有价值”）

**E-C1（前置，G1 闸，W2）：10 人 concierge 意愿测试**

| 项 | 设计 |
|---|---|
| 问题 | 用户愿不愿意在看完内容后坐下来上一节课？ |
| 设计 | 手动为 10 个真实用户各做 1 节课（G0 的 pack + 人工编排），观察 3 个数 |
| 门槛 | **6/10 走完主体、5/10 愿上第二节、3/10 提交产出** |
| 不过 | 重设模板或停；不写课程 UI |
| 成本 | 2.5 人日（含招募、记录、回访） |

**E-C2（核心）：within-subject crossover，双主终点**

| 项 | 设计 |
|---|---|
| 问题 | 同一段真实内容，上 12 分钟课 vs 只看双语字幕+查词，7 天后**任务能力**与**目标词迁移**是否更好？ |
| 设计 | **within-subject crossover**：同一用户随机顺序做 A（课）与 B（只看）；内容匹配难度；间隔 1 周洗脱；内容 counterbalance |
| 样本 | **n≈30**（首批种子；n<30 只做方向）；n≥100 才对外说“初步有效” |
| 主终点 ① | 7 天后**新的 3–5 句 can-do 任务**（同 rubric、2 名评分员盲评、κ≥0.6） |
| 主终点 ② | 7 天后 **10 个未教句子**的目标词填空（0–10） |
| 次终点 | 7 天 FSRS 保持率；完成率；产出提交率；7 天内再上一课；愿付意向 |
| 分析 | 配对检验/Wilcoxon；报 **效应量 + 95% CI**；**预注册主终点、分析计划、MDE**；不做事后挑指标 |
| 诚实边界 | n=30 不宣称显著性；不写“提分/达 B2”；只说“这节课覆盖了什么、你练了什么” |
| 成本 | 3 人日设计+分析 + 教研 1 人日 + 试点激励 |

**E-C3（V1）：产出有无的对照**

n≈30：有产出 vs 无产出，7 天迁移差异；用于决定 V1 是否加“说”。1.5 人日 + 模板 0.5 人日。

**E-C4（v1 新增）：课长假设检验 8 / 12 / 15 分钟**

| 项 | 设计 |
|---|---|
| 问题 | 12 分钟是不是最优？v0.1 把它写成“唯一有数据依据”，但它只是 n=12 的弱先验 |
| 设计 | 同一内容手工编排 3 个时长版本（8 / 12 / 15 分钟，题量与讲解按比例），随机分配，n≈30 |
| 读什么 | 完成率、产出提交率、主动时间占比、7 天再上一课、主观“太长/太短” |
| 判据 | 若 8 分钟完成率显著更高且迁移不差 → MVP 改 8；若 15 分钟迁移更高且完成不掉 → V1 主档改 15 |
| 成本 | 1.5 人日（复用 E-C2 的被试与工具） |

### 12.4 判定规则（先写死，避免事后解释）

| 结果 | 判定 |
|---|---|
| **G1 达成**（6/10 完成、5/10 愿上第二节、3/10 提交产出） | 进入 C-M2/C-M3 的正式开发；否则停或重设模板 |
| E-C2 双主终点：can-do 任务 d≥0.4 **且** 词迁移 ≥15pp，且 hard 完成 ≥50% | **继续投 V1**（15 分钟课、形式点长期回收、公课扩到 12 节） |
| 迁移差 5–15pp（或 d 0.2–0.4），完成 40–50% | **修模板**（减题/减讲解/换内容类型），再跑一轮 n≈30 |
| 迁移差 <5pp（或 d<0.2），或 hard 完成 <40% | **停/转向**：回到“翻译+查词+3 题”，或只保留“私课 concierge”作为增值服务 |
| 自由观看分钟降 >5pp | 入口/文案有问题，先修护栏再谈效果 |
| 举报率 >2% 或错误率 >1/100 或 T1 通过率 <90% | 停发新公课，回滚 prompt，补人审 |
| E-C4 指向 8 分钟 | MVP 主档改 8 分钟（模板、题量、成本表同步改） |

### 12.5 对外话术（写进 FAQ/落地页）

- 能说： “这节课覆盖了 4 个词、1 个句式；你练了 8 道题、写了 1 段话；4 个词进了复习。”
- 能说： “难度是按你的定位估计裁的，可能有一档误差。”
- 能说： “这节是试验课，我们会按你的反馈调难度和长度。”
- **不能说**： “学完达到 B2”“7 天记住 90%”“提分”“相当于雅思 X”“老师亲授”。
- 数据披露：n<100 标“初步”；报效应量/CI，不报“显著提升”。

### 附录 C：Prompt 骨架（分析 + 出题 + 产出）

**分析（call ①）**：

```
你在为一段英语视频/文章做教学分析。只输出 JSON：
{
  "gist_zh": "≤40 字，这段在讲什么",
  "register": "interview|lecture|vlog|news|essay|dialog",
  "sensitivity": ["political","religious","violence","adult","medical","financial"],
  "context_card": {
    "quote": "从下面 transcript 里逐字选 1 句（前后窗口也可）",
    "paraphrase_zh": "≤20 字，只改述，不添加事实"
  },
  "discourse": [{"from_block": 1, "to_block": 10, "function": "hook|claim|example|counterpoint|conclusion"}]
}
禁止：编造标题/频道/数字/人名；不要给教学点。
```

**出题（call ③）**：

```
为下面 5 个教学点出 6 道主测 + 2 道离场测 + 1 道不计分 gist，全部 mcq（4 选 1）或 tf。
6 道主测按档分配：basic 细节2/因果1/词义2/形式1；core 细节2/词义2/形式1/推断1；
advanced 细节1/词义2/形式1/推断或语用2。若目标里有“为什么”，因果题必须存在。
每题必须有 locator.quote（原文子串）+ block_index；答案必须能由引文推出。
干扰项：同词性、同话题、长度相近、不能靠常识排除；禁止“以上都对/都不对”。
输出 JSON：{"items":[{item_id, role, type, locator, stem, options, answer_index, explanation}], "output_task": {...}}
```

**产出反馈（call ④）**：

```
你是英语写作教练。只评下面这段学员产出，不评分、不预测考试、不比较他人。
输出 JSON：
{
  "rubric": {"task": 0-2, "target_language": 0-2, "readability": 0-2},
  "highlight": "1 个具体亮点（必须引用学员原文子串）",
  "suggestions": ["≤3 条，每条必须引用学员原文子串或明确指出缺哪个目标词"],
  "rewrite": "1 句改写对照（只改 1 处，不重写全文）"
}
禁止：打分/百分比/CEFR 等级/“你会考到 X”/编造学员没写的内容。
```

## 14. 与审稿意见的对应

### 14.1 处理原则

1. **能落成机制的落成机制**：凡评审说“纸面自洽但不可执行”的（时间盒、覆盖率、seen、缓存键、双写），一律改成代码可断言的规则或测试，不写成“注意”。
2. **算不出来的就改成能算的，并明说是改口径**：例如“主动 ≥50%”在原模板下物理不可达（上限 5.5 分钟），v1 改为 ≥45% 并公开算术，而不是悄悄换个指标名。
3. **数字上修不掩饰**：token、成本、人日、日历全部上修，并在 §14.5 列出“v0.1 → v1”对照，不保留旧数字做装饰。
4. **不采纳的意见给理由**（§14.6），并落到 §11.2 的待决策里，避免“讨论过但没人记得为什么没做”。

### 14.6 未采纳/推迟的意见与理由

| 评审意见 | 处理 | 理由 |
|---|---|---|
| “当前团队更现实的是 8–10 周” | 部分采纳 | 2.9 FTE 下 7–8 周；**1.5 FTE 下就是 12–14 周**，比评审估的更长——因为 v1 增量 26–29 人日。不再用“6 周”做承诺 |
| M1 选项 B（顺序看 4′ + 集中讲解） | 不采纳 | 与“每个点可点回原声、答错回跳”的差异化冲突；B 会把课拉到 14 分钟 |
| M2 “删掉 A2 的为什么危险” | 不采纳（选另一支） | 改加 1 道因果题 + `because` 框架；删目标等于砍掉用户最想要的“能说清楚” |
| M3 “一次生成 3 档 items，上限提到 6k” | 不采纳 | 与 M8 上修叠加到 ≈$0.021/课；且档间窗口不同，一次生成也省不掉 |
| M8 选项①（2 档 + 规则 core）/ ②（4 点 + 6 题） | 不采纳 | 三档措辞与 5 点是命题核心；用“软 4,200 / 硬 5,000 + 敏感性表”控制 |

**一句话结论**：课程化引擎值得做，但它的成败不在“生成讲解”，而在**敢不敢把课压到 12 分钟分段交错、每课只教 4 词 + 1 个形式、每个点都钉在原文证据上、4 个词真的进复习，并且承认 A2 上不了 B2 内容**；先花 7–8 人日做 G0（证内容质量）、再用 W2 的 10 人 concierge 做 G1（证意愿），G1 过了才用 7–8 周 / 80–93 人日做 3 篇自有文章公课 + 私课，单课 AI ≤$0.0162、公课全成本 ¥120——**不过就不扩，不要用 UI 掩盖内容问题**。
